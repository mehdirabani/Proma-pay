# API و routeها

## احراز هویت و مجوز

تمام routeها از Plugin Manager ثبت می‌شوند و احراز هویت و مجوز manifest دارند. عملیات تغییردهنده فقط POST را می‌پذیرد و از `Csrf::verify()` هسته استفاده می‌کند. API فعلی فقط خواندنی است؛ endpoint نوشتن عمومی یا دسترسی ناشناس تعریف نشده است.

## endpointهای API

| Method | مسیر | مجوز | پاسخ |
|---|---|---|---|
| GET | `api/plugin/inventory-partners/dashboard` | `view_inventory` | خلاصهٔ داشبورد؛ فیلد هزینه فقط برای دارندهٔ `view_costs` |
| GET | `api/plugin/inventory-partners/products` | `view_products` | حداکثر ۳۰ کالای فعال برای جست‌وجوی فرم‌ها، همراه موجودی آزاد و قیمت فروش |
| GET | `api/plugin/inventory-partners/brands` | `view_products` | تا ۳۰ برند فعال برای جست‌وجوی پیشوندی |
| GET | `api/plugin/inventory-partners/categories` | `view_products` | تا ۳۰ دستهٔ فعال برای جست‌وجوی پیشوندی |
| GET | `api/plugin/inventory-partners/contracts` | `view_sales` | تا ۳۰ قرارداد فعال/درانتظار که هنوز به فروش افزونه متصل نشده‌اند |

پارامتر اختیاری `q` برای جست‌وجوی کالا، برند، دسته و قرارداد پذیرفته می‌شود. جست‌وجوی کالا و فهرست‌ها با پیشوند متن جست‌وجو محدود و نتیجه‌ها سقف دارند تا فرم‌ها صدها گزینه را در HTML بارگذاری نکنند. پاسخ JSON از helper کنترلر core می‌آید و به session کاربر و مجوز plugin وابسته است؛ API عمومی برای اتصال سیستم دیگر در نظر گرفته نشده است.

## صفحات ماژول

تمام routeهای دیگر در manifest ثبت شده‌اند و تحت `plugin/inventory-partners/` هستند: داشبورد، کالا و قیمت‌ها، خرید، موجودی و تعدیل، فروش نقدی/قراردادی، تطبیق و مرجوعی، شرکا و آورده، دفترکل، درخواست/تأیید/پرداخت/برگشت تسویه، انتقال و دریافت/لغو، سود و زیان، گزارش CSV، تاریخچه و تنظیمات. نام دقیق مسیرها و مجوز هر مسیر منبع قطعی در `plugin.json` است.

## یکپارچگی قراردادها

- اتصال فروش قرارداد از شناسهٔ قرارداد و ردیف موجود در core استفاده می‌کند؛ picker قرارداد شناسه را در همان فرم ثبت می‌کند و مبلغ اصل با مبلغ فروش کالا کنترل می‌شود.
- پرداخت فقط از رکوردهای واجد شرایط core وارد می‌شود؛ تخصیص پرداخت با شناسهٔ پرداخت یکتا است.
- eventهای core موجود: `payment.completed` و `contract.cancelled`.
- event عمومی اصلاح یا ابطال پرداخت در نسخهٔ بررسی‌شده موجود نبود. تطبیق دستی در صفحهٔ فروش، مسیر اصلاح فعلی است.

## خطاها

خطای اعتبارسنجی با پیام فارسی در flash صفحه ثبت می‌شود. خطای غیرمنتظره در ErrorHandler ثبت و پیام عمومی همراه شناسهٔ پیگیری نمایش داده می‌شود. شکل و کدهای HTTP خطا برای مصرف‌کنندهٔ API بیرونی به‌عنوان قرارداد نسخه‌دار تثبیت نشده‌اند.
