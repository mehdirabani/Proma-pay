# راهنمای نصب و به‌روزرسانی

## پیش‌نیاز

- Proma Pay با Plugin Manager سازگار (manifest حداقل 6.0.2)
- PHP 8.1 یا جدیدتر
- MySQL 5.7 یا MariaDB 10.3 به بالا، InnoDB و utf8mb4
- دسترسی نقش مدیر برای نصب، فعال‌سازی و اعطای مجوزها

## نصب

1. از دیتابیس و فایل‌های سامانه نسخهٔ پشتیبان بگیرید.
2. بارگذاری proma-inventory-partners.zip را از صفحهٔ مدیریت افزونه‌ها انجام دهید.
3. نصب و سپس فعال‌سازی را از همان Plugin Manager انجام دهید. provider یک انبار اصلی با کد MAIN و تنظیمات پایه را در نصب اولیه ثبت می‌کند.
4. پس از فعال‌سازی، مجوزهای مورد نیاز را در مدیریت دسترسی نقش‌ها تنظیم کنید.
5. صفحهٔ تنظیمات را باز کنید، انبار پیش‌فرض، برندها، دسته‌ها، الگوی SKU و آغاز سال مالی را تنظیم کنید.
6. ابتدا شریک‌های فعال را بسازید، سپس کالا و محمولهٔ آزمایشی کم‌ارزش ثبت کنید.

Plugin Manager هنگام نصب یا به‌روزرسانی migrationهای manifest را به ترتیب نام اجرا می‌کند. ارتقا به ۱.۱.۰ ابتدا جداول برند، دسته و هزینه را می‌سازد، سپس ستون‌های محصول و رابطه‌های برند/دسته را اضافه می‌کند و نام‌های قدیمی را به فهرست مرکزی متصل می‌کند. این DDL داخل تراکنش قابل rollback نیست.

## مجوزهای کلیدی

مجوزهای `view_costs`، `view_expenses`، `record_expenses`، `view_financial_reports`، `view_partner_ledger`، `approve_settlement`، `pay_settlement`، `manage_sales` و `manage_settings` را متناسب با نقش‌های مالی/مدیریتی بدهید. routeها سمت سرور محافظت می‌شوند؛ پنهان شدن دکمه در UI کنترل دسترسی محسوب نمی‌شود.

## به‌روزرسانی

- بستهٔ جدید را از مسیر update افزونه در Proma Pay نصب کنید.
- migration جدید فقط برای نسخه‌های بعدی اضافه می‌شود؛ migration موجود را برای تغییر schema ویرایش نکنید.
- پیش از ارتقا از دیتابیس پشتیبان بگیرید و پس از migration، جست‌وجوی برند/کالا، ثبت هزینه و گزارش سال مالی را بررسی کنید.
- اسناد قطعی به‌صورت خودکار حذف نمی‌شوند. غیرفعال‌کردن افزونه داده‌های افزونه را نگه می‌دارد.
- پس از به‌روزرسانی، healthCheck و صفحه‌های انبار، دفترکل و گزارش را بررسی کنید.

## بازگشت/حذف

غیرفعال‌سازی داده‌ها را حفظ می‌کند. حذف عادی نیز جدول‌ها و اسناد مالی را پاک نمی‌کند. برای پاک‌سازی دستی داده‌ها، ابتدا با مسئول مالی و مالک داده‌ها هماهنگ کنید و پس از export و پشتیبان‌گیری، یک رویهٔ حذف جداگانه تدوین کنید؛ این بسته purge مخرب ندارد.
