# برنامهٔ Rollback

1. در صورت route conflict، خطای boot، مغایرت مانده، hook تکراری یا تخصیص اشتباه، فوراً نوشتن خرید/فروش/پرداخت/تسویه را متوقف کنید.
2. خروجی audit و شناسهٔ تمام رویدادهای successor بعد از cutover را ذخیره کنید.
3. successor را از Plugin Manager غیرفعال کنید؛ uninstall یا purge اجرا نکنید.
4. افزونهٔ قدیمی را فعال کنید. guard دوجانبه باید اجازهٔ فعال‌شدن فقط یک provider را بدهد.
5. تراکنش‌های بعد از cutover را با شناسه و hash/idempotency تطبیق دهید. چون جداول مشترک‌اند، عموماً همان داده برای کد قدیمی قابل مشاهده است؛ اگر تغییر schema افزایشی ناسازگار بوده باشد، پیش از بازگشت باید staging آن بررسی شود.
6. backup پیش از cutover فقط پس از تصمیم مسئول مالی و طرح جداگانهٔ replay برای همهٔ تراکنش‌های پس از backup قابل بازیابی است.
7. پس از تثبیت، اختلاف‌ها و علت را در گزارش migration ثبت کنید. هیچ داده‌ای برای «تمیزکردن» حذف نشود.

این rollback روی staging آزمایش نشده است؛ تا اجرای آزمایشی، نتیجهٔ آن تأییدشده اعلام نمی‌شود.
