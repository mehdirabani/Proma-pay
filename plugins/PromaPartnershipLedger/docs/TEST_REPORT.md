| ذخیره و audit دیتابیسی | موفق | ذخیرهٔ سیاست مالی در تراکنش آزمایشی، hash برابر SHA-256، ثبت audit و rollback کامل دو شریک و سیاست آزمایشی بررسی شد؛ هیچ رکورد QA باقی نماند |

| صفحهٔ انتقال موجودی legacy | مشاهده شد | پنجرهٔ رزرو باز بود اما فهرست محموله برای انتخاب وجود نداشت؛ هیچ انتقالی ثبت نشد |

## وضعیت آزمون محلی

- نسخهٔ `PromaPartnershipLedger 2.0.0-alpha.1` با تطبیق ۵۱ فایل در `C:\laragon\www\proma\plugins\PromaPartnershipLedger` برای آزمون محلی stage شد.
- دیتابیس فعال `proma_test` است. پیش از migration از آن نسخهٔ پشتیبان گرفته شد: `C:\laragon\backup\mysql\proma_test-before-ledger-2026-10-21.sql`.
- ورود مدیر انجام شد. صفحهٔ Plugin Manager نشان داد افزونهٔ قدیمی `proma-inventory-partners 1.1.2` فعال و افزونهٔ جدید `proma-partnership-ledger 2.0.0-alpha.1` شناسایی‌شده اما نصب‌نشده است.
- queryهای فقط‌خواندنی جداول عملیاتی را شمارش کردند؛ یک انبار و صفر رکورد عملیاتی برای کالا، شریک، lot، فروش، خرید، journal، تخصیص پرداخت، هزینه و تسویه دیده شد. داده‌های مشتری/قرارداد/پرداخت هسته وجود دارند و این افزونه آنها را تغییر نداده است.
- پنجرهٔ رزرو انتقال legacy نشان داد محموله‌ای برای انتخاب نیست. هیچ فروش، خرید، انتقال، پرداخت، هزینه یا تسویه‌ای ثبت نشد.
- مسیر مالی جدید پیش از نصب/فعال‌سازی HTTP 404 می‌دهد. نصب successor اجرا نشده است؛ آزمون UI، migration lifecycle و guard فعال‌سازی در انتظار تأیید نصب محلی‌اند. افزونهٔ قدیمی همچنان فعال است.

نتیجه‌های آزمون `PromaInventoryPartners 1.1.2` به successor تعمیم داده نمی‌شوند. این build هنوز از نظر آزمون رابط کامل، cutover و Production readiness تأیید نشده است.
