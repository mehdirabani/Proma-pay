# Migration و تطبیق داده

مهاجرت عملیاتی این نسخه zero-copy است: شناسه‌ها و ردیف‌های موجود در جداول `plugin_inventory_*` باقی می‌مانند. migration افزونهٔ جدید دفترکل/موجودی موازی نمی‌سازد و فقط جدول نسخه‌های مالی را اضافه می‌کند. هیچ import دوباره‌ای از کالا/فروش/journal انجام نمی‌شود.

## مراحل

1. ثبت snapshot و نسخهٔ هسته/افزونه، وضعیت registry و شمارش/جمع جداول عملیاتی، journalها، تخصیص پرداخت و تسویه با `tools/migration-snapshot.sql`.
2. تهیه و بازیابی آزمایشی backup دیتابیس و فایل‌ها.
3. نصب migration افزایشی successor روی staging درحالی‌که افزونهٔ قدیمی تنها writer فعال است.
4. اجرای تطبیق read-only بر شناسه و جمع کالا، lot، مانده، سریال/IMEI، خرید/فروش/مرجوعی، آورده، journal، پرداخت، هزینه و تسویه.
5. اجرای آزمون parity و تست‌های امنیت/رقابت روی staging.
6. پس از تأیید گزارش و مسئول داده، توقف نوشتن، غیرفعال‌کردن افزونهٔ قدیمی، فعال‌سازی successor و smoke check.
7. پایش reconciliation؛ uninstall/purge و حذف دادهٔ قدیمی بخشی از cutover نیست.

## قواعد توقف و rollback

هر اختلاف موجودی/سریال/بها، journal نامتوازن، پرداخت دوباره، ماندهٔ نامنتظر یا hook تکراری cutover را متوقف می‌کند. در بازگشت، successor را غیرفعال و نسخهٔ قدیمی را فعال کنید؛ همهٔ تراکنش‌های بعد از cutover با idempotency/reference بررسی شوند. backup پیش از cutover بدون طرح replay تراکنش‌های بعدی بازیابی نمی‌شود.

گزارش فعلی فقط ممیزی سورس است؛ تعدادها و جمع‌های زنده نامعلوم‌اند. به `MIGRATION_VERIFICATION_REPORT.md`, `CUTOVER_PLAN.md` و `ROLLBACK_PLAN.md` مراجعه کنید.
