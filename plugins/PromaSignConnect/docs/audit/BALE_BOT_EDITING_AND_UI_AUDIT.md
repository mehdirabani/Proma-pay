# ممیزی ویرایش بازوی بله و رجیستری متغیرها

## نتیجه ممیزی

- مسیر ایجاد بازو وجود داشت، اما مسیر و رابط مستقل ویرایش وجود نداشت.
- متد `save` از شناسه پشتیبانی می‌کرد، ولی فرم شناسه را ارسال نمی‌کرد و هر ویرایش، بازو را بدون بررسی نوع تغییر غیرفعال می‌کرد.
- خالی گذاشتن توکن، توکن فعلی را حذف نمی‌کرد؛ این رفتار صحیح حفظ شد.
- قابلیت‌ها برای هر بازو در `capabilities_json` ذخیره می‌شدند، اما دسترسی رویدادها فقط در نگاشت عمومی ارائه‌دهنده خوانده می‌شد.
- جدول `proma_connect_provider_event_mappings` از `provider_account_id` پشتیبانی داشت؛ نسخه ۱.۲.۰ این ستون را به مسیر واقعی مدیریت و ارسال متصل می‌کند.
- تست ارسال داخل ردیف جدول قرار داشت و در نمایش موبایل نامناسب بود.
- فعال‌سازی فقط تست موفق را کنترل می‌کرد و وجود حداقل قابلیت و رویداد مجاز را کنترل نمی‌کرد.
- رجیستری متغیرها آرایه ثابت PHP بود و نگاشت نام استاندارد به پارامتر IPPanel، SMS.ir، بله و تلگرام persistence نداشت.

## اصلاحات نسخه ۱.۲.۰

- فرم ویرایش مستقل با حفظ توکن خالی، بازتأیید فقط پس از تغییر Bot ID یا توکن، و Audit امن
- کارت‌های بازو، وضعیت‌های فارسی، عملیات مستقل، تست جدا و نمایش سلامت
- نگاشت رویداد مستقل هر بازو و کنترل آن در routing
- آرشیو امن بدون حذف تاریخچه
- رجیستری مرکزی متغیرها و نگاشت ارائه‌دهنده
- migration نسخه‌ای و بدون اجرای schema در درخواست عادی
