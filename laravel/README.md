# پرماپی — هستهٔ Laravel

این پوشه یک برنامهٔ مستقل Laravel برای ساخت تدریجی نسخهٔ جدید پرماپی است. رابط کاربری فارسی و راست‌چین است. این نسخه یک **پایهٔ اجرایی اولیه** است؛ مهاجرت کامل سامانهٔ قدیمی، قوانین مالی آن و آمادگی استقرار مالی هنوز انجام و تأیید نشده‌اند. جزئیات و مرز کار در [مستندات](docs/ARCHITECTURE.md) آمده است.

## پیش‌نیازها

- PHP 8.2 یا بالاتر با افزونه‌های `bcmath`, `ctype`, `curl`, `fileinfo`, `mbstring`, `openssl`, `pdo`, `tokenizer`, `xml` و درایور دیتابیس مورد استفاده.
- Composer 2 و Node.js سازگار با Vite 7 به همراه npm.
- SQLite برای توسعهٔ محلی یا MySQL/MariaDB برای محیط هدف؛ نسخه و تنظیمات DB را پیش از استقرار با نسخهٔ Laravel و محیط واقعی تطبیق دهید.

در محیط توسعه با PHP 8.2، این پروژه روی Laravel 12 ایجاد شده است. برای استقرار تولید، برنامهٔ ارتقا به PHP 8.3 و Laravel 13 را در نظر بگیرید و آن را پیش از مهاجرت واقعی با CI و نسخهٔ دقیق دیتابیس بازاعتبارسنجی کنید. [جدول پشتیبانی نسخه‌های Laravel](https://laravel.com/framework/docs/releases)

## نصب محلی

از همین پوشه (`laravel/`) اجرا کنید:

```sh
composer install
cp .env.example .env
php artisan key:generate
npm ci
npm run build
php artisan migrate --seed
php artisan proma:create-admin
php artisan serve
```

در PowerShell، به‌جای `cp` از `Copy-Item .env.example .env` استفاده کنید. فرمان ساخت مدیر نام، ایمیل و گذرواژه را به‌صورت تعاملی می‌گیرد؛ حساب یا گذرواژهٔ پیش‌فرضی وجود ندارد. برای محیط محلی SQLite در `.env.example` فعال است. SQLite محلی/آزمایشی را با دادهٔ واقعی پر نکنید.

## تنظیم محیط و اجرا

- پیش از هر محیط مشترک، `APP_DEBUG=false`، `APP_ENV=production`، `APP_URL` و `APP_KEY` امن و مختص همان محیط را تنظیم کنید. `.env` را به Git نفرستید.
- تنظیمات اتصال MySQL/MariaDB را در متغیرهای `DB_*` قرار دهید. ابتدا مهاجرت را روی نسخهٔ پشتیبان یا محیط آزمایشی اجرا و نتیجه را بررسی کنید؛ `migrate:fresh` داده‌ها را حذف می‌کند و فقط برای پایگاه دادهٔ دورریختنی/آزمایش است.
- برای استقرار، build فرانت را بسازید، سپس `php artisan config:cache`, `php artisan route:cache` و `php artisan view:cache` را در فرایند انتشار اجرا کنید. اجرای migration باید مرحلهٔ کنترل‌شدهٔ انتشار باشد.
- ریشهٔ وب‌سرور را دقیقاً روی `laravel/public` تنظیم کنید. ریشهٔ repository یا خود پوشهٔ `laravel` را مستقیماً منتشر نکنید.
- از TLS، پایگاه دادهٔ خصوصی، پشتیبان رمزگذاری‌شده، مدیریت امن کلیدها و پایش خطا استفاده کنید. تنظیمات واقعی استقرار در [DEPLOYMENT](docs/DEPLOYMENT.md) و محدودیت‌های امنیتی در [SECURITY](docs/SECURITY.md) است.

## قابلیت‌های فعلی

ورود کارکنان، نقش/مجوز، محدودسازی دید مشتری به شعبه، ثبت و نمایش مشتری، ارسال و بررسی پروندهٔ KYC، ثبت تغییر سقف اعتبار با دفترکل، ثبت درخواست پرداخت در حالت `pending`، API نسخهٔ ۱ با Sanctum و رابط فارسی RTL پیاده شده‌اند. پرداخت هنوز تسویه یا به اقساط تخصیص داده نمی‌شود. عقد قرارداد و ساخت اقساط، درگاه پرداخت، webhook، اتصال WordPress/WooCommerce و انتقال داده از نسخهٔ قدیمی هنوز عملیاتی نیستند.

برای فهرست کامل و وضعیت دقیق هر قلم به [FEATURE-MAP](docs/FEATURE-MAP.md) و [LEGACY-MAPPING](docs/LEGACY-MAPPING.md) مراجعه کنید.


دستورهای بررسی بیشتر و شواهد اجرای این نسخه در [TESTING](docs/TESTING.md) ثبت می‌شوند.
