## Immediate findings

1. The Laravel application is a small foundation. A model/migration is not a completed domain workflow.
2. Three DB-free Legacy financial regression scripts pass and specify allocation ordering, partial-payment reward behavior, due-date legal penalty, stale display repair, and fail-closed missing legal settings. These are porting evidence, not Laravel or MySQL evidence.
3. `LEGAL_PENALTY_CANONICAL_TRANSITION.md` conflicts with `LEGAL_PENALTY_DUE_DATE_POLICY.md`, current versioned service code, and the v156 regression on whether the legal tariff begins at referral or installment due date. Current code/test + the v1.5.14 policy agree on due-date origin; record/resolve this in Laravel docs and do not rewrite the Legacy tree.
4. Prior commit `27be765` passed 78 tests/496 assertions on disposable MariaDB 10.4.32, including credit-reservation, payment-capture and payment-correction races. Current receipt changes pass 85 tests/593 assertions on SQLite and a SQLite fresh seed; MariaDB migration/suite rerun was blocked by a disposable XAMPP server InnoDB startup assertion. This does not identify or validate the production target.
5. The current Legacy tree is heavily modified; source files are read-only evidence for this task.
