## هدف Workflow

هدف این Workflow این است که کاربران مجاز بتوانند گزارش‌های مالی، قراردادی، اقساط، پرداخت‌ها، مشتریان، معوقات، حقوقی، عملکرد اپراتورها، بکاپ، آپدیت، پلاگین‌ها و گزارش‌های سیستمی را مشاهده، فیلتر و در قالب‌های مجاز خروجی بگیرند.

گزارش‌ها باید دقیق، امن، قابل فیلتر، قابل کنترل با Permission و قابل خروجی گرفتن باشند.

گزارش‌ها نباید اطلاعات حساس را برای نقش‌های غیرمجاز نمایش دهند.

## تعریف Report

Report یعنی نمایش ساختاریافته داده‌های سیستم با فیلتر، مرتب‌سازی، خلاصه آماری و کنترل دسترسی.

گزارش می‌تواند داده را از چند Domain ترکیب کند، اما نباید منطق اصلی Domainها را دور بزند.

مثال:

گزارش اقساط نباید خودش مبلغ مانده را با فرمول جدا محاسبه کند.  
باید از داده معتبر یا Financial Calculations Domain استفاده کند.

---

## تعریف Export

Export یعنی تبدیل نتیجه یک گزارش به فایل قابل دانلود.

فرمت‌های پیشنهادی:

- CSV
- XLSX
- PDF
- JSON در آینده

قانون مهم:

Export نباید راهی برای دور زدن Permission باشد.  
هر چیزی که کاربر حق دیدن آن را در UI ندارد، نباید در فایل خروجی هم وجود داشته باشد.

## مراحل اصلی Workflow

نمای کلی مراحل:

1. کاربر وارد صفحه Reports می‌شود.
2. نوع گزارش را انتخاب می‌کند.
3. Permission بررسی می‌شود.
4. Scope کاربر اعمال می‌شود.
5. فیلترها توسط کاربر وارد می‌شوند.
6. فیلترها Validate می‌شوند.
7. Query گزارش ساخته می‌شود.
8. داده‌ها با محدودیت دسترسی خوانده می‌شوند.
9. گزارش در UI نمایش داده می‌شود.
10. کاربر در صورت Permission درخواست Export می‌دهد.
11. فرمت خروجی انتخاب می‌شود.
12. ستون‌های مجاز بررسی می‌شوند.
13. فایل خروجی ساخته می‌شود.
14. فایل در صورت حساس بودن در Private Storage ذخیره می‌شود.
15. Audit Log ثبت می‌شود.
16. لینک دانلود امن نمایش داده می‌شود.

---

## مشاهده گزارش

### مراحل

1. کاربر وارد منوی گزارش‌ها می‌شود.
2. سیستم لیست گزارش‌های قابل مشاهده را بر اساس Permission نمایش می‌دهد.
3. کاربر یک گزارش را انتخاب می‌کند.
4. فرم فیلتر گزارش نمایش داده می‌شود.
5. کاربر فیلترها را وارد می‌کند.
6. سیستم Permission و Scope را بررسی می‌کند.
7. داده‌ها خوانده و خلاصه‌سازی می‌شوند.
8. جدول گزارش نمایش داده می‌شود.

### قوانین

- کاربر فقط گزارش‌های مجاز را ببیند.
- مشتری فقط گزارش‌های خودش را ببیند.
- اپراتور فقط گزارش‌های Scope خودش را ببیند.
- وکیل فقط گزارش‌های حقوقی مجاز را ببیند.
- گزارش مالی داخلی نباید برای مشتری نمایش داده شود.
- فیلترها نباید باعث دور زدن Scope شوند.
- Query گزارش باید سمت سرور کنترل شود.

- لینک دانلود بکاپ در گزارش عمومی قرار نگیرد.
- خطاهای حساس نباید برای نقش غیرمجاز نمایش داده شوند.
- Export این گزارش باید Audit Log داشته باشد.

## خروجی گرفتن از گزارش

فرمت‌های خروجی پیشنهادی:

| فرمت | کاربرد |
|---|---|
| `csv` | خروجی سبک و عمومی |

| `pdf` | خروجی رسمی یا چاپی |
| `json` | خروجی API یا توسعه آینده |

### مراحل Export

1. کاربر در صفحه گزارش روی Export کلیک می‌کند.
2. فرمت خروجی را انتخاب می‌کند.
3. ستون‌های خروجی را انتخاب می‌کند.
4. Permission خروجی بررسی می‌شود.
5. فیلترها دوباره سمت سرور Validate می‌شوند.
6. Query با Scope مجاز اجرا می‌شود.
7. فایل خروجی ساخته می‌شود.
8. فایل در Private Storage ذخیره می‌شود، اگر حساس باشد.
9. Audit Log ثبت می‌شود.
10. لینک دانلود امن نمایش داده می‌شود.

### قوانین

- Export باید همان Scope نمایش UI را رعایت کند.
- Export نباید ستون غیرمجاز اضافه کند.
- Export گزارش حساس باید Audit Log داشته باشد.
- Export بزرگ باید محدود یا صف‌بندی شود.
- فایل خروجی نباید در Public Storage قرار بگیرد، مگر گزارش عمومی و غیرحساس باشد.

## Validationها

### گزارش

- report_type معتبر باشد.
- کاربر Permission مشاهده گزارش را داشته باشد.
- فیلترها معتبر باشند.
- date_from و date_to معتبر باشند.
- Scope کاربر اعمال شود.
- ستون‌های انتخابی مجاز باشند.
- sort_by در لیست ستون‌های مجاز باشد.
- per_page از حد مجاز بیشتر نباشد.

### Export

- export_format معتبر باشد.
- کاربر Permission خروجی داشته باشد.
- تعداد ردیف‌ها از حد مجاز بیشتر نباشد، مگر Permission خاص وجود داشته باشد.
- فایل خروجی در مسیر امن ساخته شود.
- داده‌های حساس بدون Permission وارد خروجی نشوند.
- CSRF معتبر باشد.
- فیلترهای Export دوباره سمت سرور بررسی شوند.
