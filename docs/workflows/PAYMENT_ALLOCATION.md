# تخصیص پرداخت

پیش از ثبت، رکورد قرارداد و اقساط با `FOR UPDATE` قفل می‌شوند. مبلغ‌ها به صورت عدد صحیح تومان در لایه‌ی محاسبه پردازش و به DECIMAL ذخیره می‌شوند. allocation منفی، over-allocation و ترکیب چند قرارداد در این نسخه ممنوع است.

callback درگاه باید idempotency key داشته باشد و فقط پس از verify درگاه پرداخت را موفق کند. اصلاحیه پرداخت رکورد اصلی را حذف نمی‌کند و snapshot و لاگ مالی نگه می‌دارد.
