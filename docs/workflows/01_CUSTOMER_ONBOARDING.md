## هدف Workflow

هدف این Workflow این است که مشتری بتواند وارد سیستم شود، حساب کاربری مشتری ایجاد کند، اطلاعات پایه خود را تکمیل کند، مدرک هویتی ارسال کند و بعد از بررسی مدیر، وضعیت احراز هویت او مشخص شود.

این فرآیند باید ساده، امن، قابل پیگیری و قابل اعتماد باشد.

نتیجه نهایی این Workflow یکی از حالت‌های زیر است:

- مشتری ثبت‌نام کرده ولی پروفایل ناقص دارد.
- مشتری پروفایل کامل دارد ولی احراز هویت نشده است.
- مشتری مدرک هویتی ارسال کرده و منتظر بررسی است.
- مشتری احراز هویت شده و تیک آبی دارد.
- مدرک مشتری رد شده و باید دوباره ارسال کند.

11. آیتم بررسی برای مدیر ساخته می‌شود.

## بررسی مدرک هویتی

بررسی مدرک باید در Review Center انجام شود.

بخش پیشنهادی:

```text
Review Center > Identity Documents
```

### مراحل

1. مدیر یا Review Manager وارد لیست مدارک در انتظار بررسی می‌شود.
2. Permission بررسی می‌شود.
3. مدرک از مسیر امن نمایش داده می‌شود.
4. اطلاعات مشتری نمایش داده می‌شود.
5. مدیر مدرک را بررسی می‌کند.
6. مدیر یکی از گزینه‌های تأیید یا رد را انتخاب می‌کند.
7. نتیجه بررسی ثبت می‌شود.
8. وضعیت مشتری بروزرسانی می‌شود.
9. فایل‌های غیرضروری طبق Policy حذف یا آرشیو می‌شوند.
10. Notification و Bot Message ارسال می‌شود.
11. Audit Log ثبت می‌شود.

## تأیید مدرک هویتی

وقتی مدرک تأیید می‌شود:

- وضعیت مشتری `identity_verified` شود.
- فیلد `identity_verified_at` ثبت شود.
- فیلد `identity_verified_by` ثبت شود.
- تیک آبی مشتری فعال شود.
- مدرک قبلی در صورت وجود طبق Policy حذف شود.
- Timeline ثبت شود.
- Audit Log ثبت شود.
- Notification برای مشتری ارسال شود.
- Bot Message برای مشتری ارسال شود.

پیام پیشنهادی مشتری:

```text
مدرک هویتی شما با موفقیت تأیید شد.
```

## رد مدرک هویتی

وقتی مدرک رد می‌شود:

- وضعیت مشتری `identity_rejected` شود.
- دلیل رد ثبت شود.
- فایل مدرک ردشده طبق Policy حذف شود.
- امکان ارسال دوباره مدرک برای مشتری فعال بماند.
- Timeline ثبت شود.
- Audit Log ثبت شود.
- Notification برای مشتری ارسال شود.
- Bot Message برای مشتری ارسال شود.

دلیل رد باید واضح و محترمانه باشد.

نمونه دلایل:

- تصویر واضح نیست.
- اطلاعات مدرک خوانا نیست.
- مدرک با اطلاعات پروفایل همخوانی ندارد.
- فایل ارسالی مدرک معتبر نیست.
- تصویر ناقص ارسال شده است.

---

## تیک آبی مشتری

تیک آبی نشان‌دهنده احراز هویت موفق مشتری است.

قوانین:

- فقط بعد از تأیید مدرک فعال شود.
- مشتری نتواند خودش تیک آبی را فعال کند.
- حذف یا غیرفعال کردن تیک آبی باید Permission و Audit Log داشته باشد.
- تیک آبی در کارت مشتری، پروفایل مشتری و لیست مشتریان نمایش داده شود.
- تیک آبی نباید به معنی خوش‌حسابی باشد؛ فقط احراز هویت است.

## Validationها

### ثبت‌نام

- شماره موبایل الزامی است.
- شماره موبایل باید معتبر باشد.
- شماره موبایل نباید تکراری باشد.
- نام و نام خانوادگی نباید خالی باشد.
- رمز عبور در صورت استفاده باید حداقل امنیت را داشته باشد.

### پروفایل

- کد ملی در صورت الزامی بودن باید معتبر باشد.
- کد ملی نباید برای مشتری دیگر ثبت شده باشد.
- آدرس باید طول مناسب داشته باشد.
- تاریخ تولد نباید آینده باشد.
- اطلاعات حساس باید Escape و Sanitized شوند.

### مدرک هویتی

- فایل الزامی است.
- حجم فایل حداکثر 1MB باشد.
- پسوند مجاز باشد.
- MIME Type معتبر باشد.
- فایل اجرایی نباشد.
- مشتری فقط برای خودش مدرک ارسال کند.

### تست‌های امنیتی

- مشتری نتواند مدرک مشتری دیگر را ببیند.
- کاربر بدون Permission نتواند مدرک را تأیید کند.
- فایل با پسوند خطرناک رد شود.
- CSRF نامعتبر رد شود.
- مسیر Private Storage مستقیم قابل مشاهده نباشد.

### تست‌های UI

- فرم ثبت‌نام در موبایل درست باشد.
- Upload در موبایل درست کار کند.
- خطاها زیر فیلدها نمایش داده شوند.
- Toast موفقیت و خطا درست نمایش داده شود.

## چک‌لیست پیاده‌سازی

قبل از پیاده‌سازی این Workflow بررسی شود:

- [ ] جدول customers آماده است.
- [ ] وضعیت‌های احراز هویت تعریف شده‌اند.
- [ ] Private Storage فعال است.
- [ ] تنظیمات حجم و فرمت فایل خوانده می‌شود.
- [ ] Review Center برای مدارک وجود دارد.
- [ ] Permissionهای بررسی مدارک تعریف شده‌اند.
- [ ] Notificationهای لازم آماده هستند.
- [ ] Bot Message در صورت فعال بودن ساخته می‌شود.
- [ ] Timeline ثبت می‌شود.
- [ ] Audit Log برای تأیید و رد وجود دارد.
- [ ] Security Log برای دسترسی غیرمجاز وجود دارد.
- [ ] UI مطابق UI Constitution است.

## Definition of Done

این Workflow زمانی کامل است که:

- مشتری بتواند ثبت‌نام کند.
- مشتری بتواند پروفایل خود را تکمیل کند.
- مشتری بتواند مدرک هویتی امن آپلود کند.
- مدرک در Private Storage ذخیره شود.
- مدیر مجاز بتواند مدرک را بررسی کند.
- تأیید مدرک باعث فعال شدن تیک آبی شود.
- رد مدرک دلیل داشته باشد و امکان ارسال دوباره وجود داشته باشد.
- مشتری فقط اطلاعات و فایل‌های خودش را ببیند.
- Notification، Bot Message، Timeline، Log و Audit ثبت شوند.
- UI ساده، RTL، Responsive و قابل فهم باشد.
- هیچ اطلاعات حساس یا مسیر فایل خصوصی افشا نشود.
