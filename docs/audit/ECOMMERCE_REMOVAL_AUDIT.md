# ممیزی خروج ایمن فروشگاه داخلی

تاریخ ممیزی: ۱۴۰۵/۰۶/۱۵  
نسخه مبنا: Proma Pay 1.5.8

## دامنه شناسایی‌شده

فروشگاه داخلی در اجزای زیر وجود دارد:

| جزء | مسیر / منبع | تصمیم مهاجرت |
| --- | --- | --- |
| کنترلر فعال | `controllers/EcommerceController.php` | مسدودسازی مسیرهای عملیاتی؛ نگهداری موقت کد تا پایان دوره بایگانی |
| مدل و سبد نشست | `models/Ecommerce.php` | عدم فراخوانی در اجرای عادی؛ داده‌های پیشین فقط‌خواندنی باقی می‌ماند |
| ویوهای فروشگاه | `views/ecommerce/*` | از ناوبری و مسیر عمومی خارج می‌شوند؛ حذف فیزیکی فقط در انتشار بزرگ بعدی و پس از خروجی بایگانی |
| مسیر پیش‌فرض | `core/Router.php` | دیگر نباید مهمان را به فروشگاه هدایت کند |
| هدر و سایدبار | `views/layouts/app.php`, `views/layouts/public.php` | سبد، فروشگاه و عملیات خرید داخلی حذف می‌شوند |
| داشبورد مشتری | `controllers/DashboardController.php`, `views/dashboard/customer.php` | کارت سفارش داخلی با سوابق اعتبار/قرارداد جایگزین می‌شود |
| ورود و ایمیل | `controllers/AuthController.php`, `helpers/EmailService.php` | بازگشت به checkout و پیوند پرداخت سفارش حذف می‌شود |
| تنظیمات | `models/Settings.php`, `controllers/SettingsController.php`, `views/settings/index.php` | فلگ‌های فروشگاه بازنشسته می‌شوند؛ مقدارهای قبلی برای سازگاری باقی می‌مانند |
| داده‌های تاریخی | چهار جدول `ecommerce_*` در install و migrationهای ۱۴۰۵/۰۴/۱۹ و ۱۴۰۵/۰۴/۲۰ | بدون حذف، تغییر ساختار یا نوشتن جدید؛ فقط بایگانی/خروجی مجاز است |
| CSS | بخش‌های `.proma-*` فروشگاهی در `assets/css/app.css` | پس از قطع همه مصرف‌کننده‌ها با ابزار تحلیل استفاده پاک‌سازی می‌شود، نه در همان migration |

## ریسک‌های قطعی

1. حذف مستقیم `EcommerceController` پیش از تغییر Router باعث خطای 404 یا حلقه ورود می‌شود.
2. حذف جدول‌ها سوابق سفارش و درخواست اقساط قدیمی را از بین می‌برد.
3. حذف سبد از layout بدون حذف redirectهای ورود می‌تواند مشتری را به مسیر بازنشسته هدایت کند.
4. اجرای عملیات schema در درخواست صفحه، با معماری هاست اشتراکی و محدودیت نرخ درخواست ناسازگار است.

## راهبرد مصوب

1. مسیرهای نوشتنی فروشگاه در انتشار بعدی بازنشسته و پاسخ هدایت‌شده/قابل‌فهم می‌گیرند.
2. ثبت سفارش، checkout، محصول و سبد جدید داخلی مجاز نخواهد بود.
3. جدول‌ها، سوابق و قابلیت خروجی تا پایان دوره نگهداری فقط‌خواندنی می‌مانند.
4. کالا، سفارش و پرداخت جدید از WooCommerce فقط از طریق API امضاشده، صف پایدار و idempotency وارد Proma Pay می‌شود.
5. هیچ migration یا تغییر schema در مسیر HTTP عادی اجرا نمی‌شود.
6. حذف فیزیکی کد و CSS فروشگاهی فقط پس از گزارش مصرف‌صفر، backup قابل بازیابی و تایید انتشار بزرگ انجام می‌شود.

## معیار پایان مهاجرت

- هیچ route عملیاتی `ecommerce/*` برای ایجاد/ویرایش سفارش قابل دسترس نباشد.
- مسیر مهمان به `auth/login` برود.
- اطلاعات مالی قرارداد مستقل از جدول‌های فروشگاه داخلی باشد.
- سوابق قبلی قابل مشاهده یا خروجی برای مدیر مجاز باشند.
- اتصال WooCommerce در یک دیتابیس مشترک انجام نشود و هیچ webhook دوباره باعث ایجاد قرارداد یا پرداخت تکراری نشود.
