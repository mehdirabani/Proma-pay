# Proma Pay UI/UX audit — 2026-10-04

## Audit scope

This review covers the application shell, role-based dashboards and navigation, shared design tokens and styles, client-side interactions, 76 core PHP view files, 44 plugin view files, and 34 core controllers. It is a source-based audit of the current working tree, which already contains unrelated uncommitted edits. Those edits were preserved.

The product serves administrators, operators, lawyers, and customers. Main operational tasks include finding customers and contracts, collecting or recording payments, following overdue installments, handling legal cases, and managing users. This review does not change domain rules or payment behavior.

## User goal and accessibility target

Help each role identify its current location and next action, then complete financial and operational tasks with consistent RTL layouts across desktop, tablet, and mobile. Accessibility target: WCAG 2.2 AA considerations, with source-level checks for semantics, names, focus, and responsive target size.

## Strengths

- One shared RTL application shell owns role-based navigation, page content, and the mobile quick-navigation bar.
- The current design system already defines a spacing scale, localized date and money formatting, visible focus styles, reduced-motion behavior, compact mobile table cards, and 44px controls for several touch layouts.
- Shared modal code includes dialog labels, focus return, Escape handling, and a keyboard focus loop.
- Core customer, contract, installment, overdue, payment, legal, and user flows include search/filter controls, pagination, and empty-state copy.
- Destructive operations generally use a confirmation step and explain the effect.

## Findings before implementation

Finding counts: **0 P0, 2 P1, 5 P2, 0 P3**.

| ID | Severity | Page / component | Issue and impact | Proposed solution |
| --- | --- | --- | --- | --- |
| A1 | P1 | Shared app header | Search and theme toggles are rendered as a `span` and `div`; the search close affordance is an icon element. They have click handlers but are not keyboard controls and expose no reliable accessible name or expanded/pressed state. | Use labeled buttons, give search a named search landmark, and synchronize `aria-expanded` / `aria-pressed` with the existing behavior. |
| A2 | P1 | Core and plugin data tables | Table headers have no explicit `scope="col"`, leaving header associations implicit across dense lists. | Add column scope to ordinary one-row table headers in the server-rendered templates. |
| A3 | P2 | Shared AJAX filters | Filter result messages update in the DOM, but the status node is not a live region; screen-reader users may not hear loading, success, or retry guidance. | Mark the shared status node as a polite, atomic status region when the filter initializes. |
| A4 | P2 | Shared controls | Small buttons are 38px high and icon buttons 42px, with 38px header actions at the narrowest breakpoint. These targets are hard to tap accurately. | Set a shared 44px compact-target token and use it for small buttons, icon actions, and visible header controls. |
| A5 | P2 | Design system and customer detail | Page title uses an `h4` even though it is the page heading; the customer detail template nests a second `<main>` inside the layout’s `<main>`. The document outline and landmark structure are therefore unclear. | Use an `h1` for the shell page title, demote the customer name to the next level, and use a section instead of a nested main landmark. |
| A6 | P2 | Shared theme tokens | Palette, radius, spacing, and control values are defined in `app.css`, `design-system/tokens.css`, and `components/v2-system.css`; overlapping values differ, so component styling depends on cascade order. | Keep the live values in the design-token file and retain compatibility aliases for existing CSS consumers. |
| A7 | P2 | Dark theme | Dark mode exists, but the newer `--pp-*` shell tokens are static while older dark rules mainly override `--proma-*`. The core shell can remain light when the theme toggle is active. | Reconcile the theme token mapping and verify every shared surface in a running panel before claiming full dark-mode coverage. |

## Evidence limits

The local PHP development server started, but the configured local database refused the connection while rendering `auth/login` (`PDOException` in `Model.php`). No authenticated route could be rendered. The in-app browser showed the application error state; it did not provide an accepted product-screen screenshot. Accordingly, layout appearance, real data density, responsive overflow, browser-console state, and end-to-end workflows remain unverified. The implementation below is source-grounded and must not be described as a complete visual or WCAG audit.

2. Apply explicit table-header scope across core and plugin templates.
3. Raise compact interactive targets to the project’s 44px touch target.
4. Correct page heading and landmark semantics.
5. Consolidate token values while preserving compatibility aliases.
6. Improve customer-detail tab keyboard support and unify its surface colors with the shared theme.
7. Re-run syntax and repository checks; leave database-backed visual and workflow checks listed as remaining until the local DB is available.

## Post-implementation status

### UI/UX audit summary

- Findings: 0 critical, 2 high, 5 medium, 0 low.
- Six findings are implemented at source level. The dark-theme token and customer-detail surface gaps were also addressed in CSS; visual appearance remains unverified, so A7 is only partially closed pending a working runtime.
- No business rules, payment calculations, routes, or data contracts were intentionally changed.

### Major problems found

- Shared header actions were not keyboard-operable buttons and lacked state announcements.
- Table column headers had no explicit association in server-rendered templates.
- AJAX filter feedback was not announced to assistive technology.
- Compact action targets fell below the 44px touch-size goal.
- The shell used an `h4` for its page title and the customer detail page nested a second main landmark.
- Design tokens were duplicated across style sheets, and dark-mode coverage did not follow the newer token layer.

### Improvements implemented

- Replaced global search, search-close, and theme controls with named buttons; added a named search landmark, synchronized expanded/pressed states, search focus/return behavior, and a skip link.
- Changed the shell title to `h1`, demoted the customer name to `h2`, removed the nested main landmark, and made success messages polite status regions.
- Added `scope="col"` to **576 column-header cells in 101 table header groups across 59 core/plugin view files**. A follow-up scan found no unscoped headers in those groups.
- Added a polite atomic live region to shared AJAX filter status messages.
- Raised shared small and icon controls, narrow header actions, sidebar submenu links, contract/settings tabs, and customer quick-menu actions to 44px.
- Added roving tab focus and RTL-aware Arrow/Home/End keyboard behavior to the customer detail tabs.
- Reconciled the new shell and customer-detail dark colors with the shared tokens.

### Architecture changes

- `design-system/tokens.css` now owns the shared palette, semantic colors, spacing, radius, shadows, control sizes, and compatibility aliases.
- Removed duplicate palette/spacing token blocks from `app.css` and `components/v2-system.css`; responsive layout overrides remain local to their breakpoints.
- Preserved the existing server-rendered pages and legacy CSS consumers rather than introducing a broad component migration.

### Pages improved

- Shared authenticated shell and public/auth layouts.
- Login, registration, password recovery, and password reset feedback regions.
- Customer detail page: semantic landmarks, heading hierarchy, theme surfaces, and accessible tab interaction.
- Table-bearing core and plugin views across customer, contract, installment, payment, legal, user, dashboard, and plugin workflows.

### Components refactored

- Global search and theme controls; shell page header and skip link; AJAX filter status; compact/icon/header buttons; customer-detail tabs; shared table column headers; design tokens.
- Existing modal lifecycle, table-to-card behavior, role navigation, and destructive confirmation flows were preserved after source review.

### Accessibility improvements

- Keyboard-operable named header controls, search landmark, expanded/pressed state, focus handling, skip link, polite success/status announcements, explicit table header scopes, corrected heading/landmark structure, and RTL-aware customer tabs.
- Source-level changes were not represented as a WCAG conformance claim. Contrast, screen-reader output, and keyboard paths still need browser verification.

### Responsive improvements

- Shared small/icon/header targets, submenu links, contract/settings tabs, and customer tabs/actions now use a 44px minimum while preserving compact horizontal tab layouts.
- Existing mobile navigation and table-card patterns were preserved. Viewports at 375, 430, 768, 1024, 1280, 1440, and 1920px could not be inspected in the real application because the database did not start.

### Removed legacy code

- Removed duplicate shared token blocks from `app.css` and `components/v2-system.css`.
- No component or asset was deleted: the source review did not establish that any remaining legacy styles or assets were unused safely.

### Validation

- JavaScript syntax: passed for `assets/js/app.js` and `assets/js/v2-system.js`.

- Dark-mode surfaces, contrast, focus visibility, and screen-reader announcements need verification in a working browser session.
