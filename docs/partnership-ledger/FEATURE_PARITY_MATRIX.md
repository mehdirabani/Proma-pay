# ماتریس تطبیق قابلیت و وضعیت توسعه

مبنای نسخهٔ قدیمی: `PromaInventoryPartners 1.1.2`. «موجود» به معنی وجود در سورس/گزارش تست نسخهٔ قدیمی است؛ به معنی تأیید روی دیتابیس زنده نیست. وضعیت افزونهٔ جدید تا زمان اجرای کد، جداگانه ثبت می‌شود.

| قابلیت | افزونهٔ قدیمی | وضعیت هدف در `PromaPartnershipLedger` | شکاف یا مدرک لازم |
|---|---|---|---|
| کاتالوگ کالا و SKU/بارکد | موجود | استفاده از همان جداول و serviceها | تنوع، تصویر و کاتالوگ پیشرفته نیاز توسعه دارد |
| دسته و برند | موجود | حفظ داده و مسیرها | تطبیق تعداد/شناسه‌ها در staging |
| تأمین‌کننده | موجود، اطلاعات پایه | حفظ مرجع | بدهی اعتباری، سررسید و پرداخت جزئی تکمیل شود |
| انبار چندگانه | موجود | حفظ همان انبارها | آزمون تطبیق کلید/مانده لازم است |
| محموله و بهای تمام‌شده | موجود | حفظ همان lotها و مانده‌ها | تطبیق ریالی هر lot لازم است |
| سریال/IMEI | موجود | حفظ همان رکوردهای سریالی | تطبیق شمارش و وضعیت هر سریال الزامی است |
| انتقال و تعدیل موجودی | موجود | حفظ service و journal موجود | شمارش دوره‌ای/تأیید مدیر غایب است |
| خرید چندردیفی | محدود؛ نسخهٔ فعلی تک‌ردیفی | توسعه | آزمون تخصیص هزینه و سرمایه بین خطوط لازم است |
| فروش نقدی | موجود | حفظ همان فروش‌ها | رگرسیون عددی و عدم فروش دوباره لازم است |
| فروش اقساطی متصل به قرارداد | موجود | حفظ قرارداد/پرداخت core و فروش افزونه | سیاست قیمت‌گذاری و سود مدت بازپرداخت باید افزوده شود |
| فروش چندردیفی | محدود؛ نسخهٔ فعلی تک‌ردیفی | توسعه | تطبیق بهای تمام‌شده و سهم در سطح خط لازم است |
| مرجوعی کامل | موجود | حفظ سند معکوس | رگرسیون و کنترل موجودی لازم است |
| مرجوعی جزئی | غایب | توسعه | کنترل چندمرجوعی، سریال و تخصیص مالی لازم است |
| شرکا و سهم مالکیت | موجود در مدل محموله | اتصال به مشارکت و تاریخ مؤثر | مالکیت/سود/زیان مستقل و چند مشارکت غایب‌اند |
| آورده سرمایه | موجود | حفظ دفتر و رویدادها | تطبیق مانده شریک لازم است |
| دفترکل دوطرفه و دفتر شریک | موجود در `plugin_inventory_*` | همان دفترکل ادامه یابد | ایجاد دفترکل موازی ممنوع؛ تطبیق مانده لازم است |
| هزینه و تخصیص شرکا | موجود پایه | حفظ مرجع | قواعد چندنوعی و تخصیص فاکتور تکمیل شود |
| کمیسیون PromaAccounting | اتصال اثبات‌نشده | adapter بدون ثبت دوبارهٔ هزینه | آزمون روی نصب دارای Accounting لازم است |
| درآمد/هزینه تعمیرات | اتصال اثبات‌نشده | adapter اختیاری | آزمون روی PromaRepair لازم است |
| پاداش معرفی | اتصال اثبات‌نشده | adapter اختیاری | جلوگیری از دوباره‌شماری با Affiliate لازم است |
| تأمین‌کنندهٔ مالی اقساط | غایب | توسعه | دارندهٔ طلب/سود، سیاست تسویه و وصول لازم است |
| نگهداری/بازسرمایه‌گذاری سود | غایب | توسعه | ماندهٔ قابل برداشت و سقف برداشت لازم است |
| بستن ماه و تسویهٔ نهایی | غایب | توسعه | دورهٔ غیرقابل‌ویرایش و گزارش امضا لازم است |
| version و snapshot سیاست | محدود به snapshot موجودی/سهم | گسترش نسخه‌دار | اثرنکردن تنظیمات جدید بر گذشته باید اثبات شود |
| Migration بدون کپی داده | migration موجود فقط schema را ایجاد می‌کند | migration zero-copy روی جداول فعلی | شمارش و جمع‌های قبل/بعد از registry زنده لازم است |
| نقش‌ها و audit | مجوزهای افزونه و activity log | نگاشت مجوزها به شناسهٔ جدید | permissionهای role فعلی باید export/تطبیق شوند |
| بستهٔ نصب و انتشار | بستهٔ successor تهیه می‌شود | ZIP با ریشهٔ صحیح افزونه | نصب روی staging و ارتقا باید تأیید شود |

## قاعدهٔ پذیرش

هیچ ردیفی که «توسعه»، «تطبیق» یا «غایب» است در این نسخه، قابلیت کامل‌شده محسوب نمی‌شود. افزونهٔ قدیمی تا زمان تکمیل موارد حیاتی و امضای تطبیق فعال/نگهداری می‌شود؛ این مخزن به‌تنهایی مجوز غیرفعال‌کردن یا حذف runtime نیست.
