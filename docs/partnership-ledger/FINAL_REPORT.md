# گزارش نهایی این نوبت

تاریخ: ۲۰۲۶-۱۰-۲۱
نسخه: `PromaPartnershipLedger 2.0.0-alpha.1`
وضعیت: بستهٔ installable برای بازبینی/staging؛ هنوز جایگزین Production نیست.

## انجام‌شده

- ممیزی سورس فعلی و ماتریس تطبیق قدیم/جدید ثبت شد.
- successor مستقل با provider، namespace، شناسه و مجوزهای جدید ساخته شد.
- دادهٔ عملیاتی موجودی، فروش و دفترکل از همان جداول `plugin_inventory_*` استفاده می‌کند؛ migration جدید فقط جدول نسخه‌های مالی را اضافه می‌کند.
- guard فعال‌سازی در هر دو provider اضافه شد تا دو افزونه هم‌زمان فعال نباشند.
- موتور محاسبهٔ اقساط integer-Rial و ثبت نسخهٔ تغییرناپذیر سیاست مالی با SHA-256 اضافه شد.
- برنامهٔ migration، cutover، rollback، استقلال runtime و گزارش تطبیق همراه بسته ثبت شدند.

## باقی‌مانده‌های مسدودکنندهٔ cutover

- شمارش/جمع واقعی دیتابیس، IMEIها، lotها، سرمایه، journal، پرداخت و تسویه تطبیق نشده است.
- سیاست اقساط هنوز مبلغ قرارداد core را تغییر نمی‌دهد و Snapshot فروش ندارد.
- چندمشارکتی/عضویت‌های مؤثر، تراکنش چندردیفی، مرجوعی جزئی، شمارش انبار، بدهی تأمین‌کننده، نگهداری سود، تسویهٔ تأمین‌کنندهٔ مالی، بستن ماه و تسویهٔ نهایی کامل نیستند.
- اتصال‌های Accounting/Repair/Affiliate و hook اصلاح پرداخت نیازمند توسعه و آزمون staging هستند.
- permissionهای role به شناسهٔ جدید خودکار نگاشت نشده‌اند.

## آزمون

- بررسی syntax جاوااسکریپت موفق بود.
- PHP domain/manifest/syntax و آزمون‌های MySQL اجرا نشدند؛ PHP CLI و DB fixture در این محیط در دسترس نبودند.
- هیچ آزمون نصب/رابط یا cutover اجرا نشده است.

## تصمیم عملیاتی

افزونهٔ قدیمی در این کار غیرفعال، حذف یا purge نشده است. تا تکمیل parity و گزارش migration روی staging/دادهٔ واقعی، cutover انجام نشود.
