# گزارش بررسی و تحویل V4.0.4

## مشکلات ریشه‌ای رفع‌شده

۱. سرویس restore فقط SQL قدیمی را وارد می‌کرد. در بکاپ واقعی، `payment_requests` فیلدهای `error_message` و `updated_at` را نداشت و outbox از نام‌ها/فیلدهای قدیمی استفاده می‌کرد. اجرای دوبارهٔ migrationهای سازگاری و بررسی ساختار واقعی، این ناسازگاری را اصلاح کرد.

۲. DDL در MySQL با rollback معمولی بازنمی‌گردد. مسیر قبلی پس از شکست SQL یا کپی فایل، recovery نداشت. نسخهٔ جدید dump ایمنی را دوباره اعمال و فایل‌های تغییرکرده را از journal برمی‌گرداند. جدول‌های خارج از snapshot نیز حذف می‌شوند. مستند رفتار DDL: [MySQL 8.4](https://dev.mysql.com/doc/refman/8.4/en/implicit-commit.html).

۳. بکاپ قبلی جدول‌ها را در زمان‌های متفاوت می‌خواند. اکنون InnoDB از یک snapshot و آرشیو دارای MyISAM از قفل خواندن همهٔ جدول‌ها استفاده می‌کند.

۴. درخواست پرداخت با وضعیت failed دوباره قابل پردازش نبود. اکنون انتقال اتمی failed → processing با همان payload و همان کاربر، فقط به یک retry اجازهٔ اجرا می‌دهد. کاربر یا مبلغ/ساعت متفاوت رد می‌شود.
