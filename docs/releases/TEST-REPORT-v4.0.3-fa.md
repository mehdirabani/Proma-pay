# گزارش تست Proma Pay V4.0.3 — Candidate

تاریخ اجرا: ۲۰۲۶-۱۰-۰۸. همه‌ی تست‌های مرورگری روی localhost یا پایگاه‌های کپی‌شده انجام شدند.

## نتایج موفق

- نصب فعال `http://proma.test` از 4.0.0 به 4.0.2 با بسته‌های updater و migration موفق شد؛ صفحه پس از ارتقا HTTP 200 بود. نصب زنده برای این بررسی در V4.0.2 باقی ماند.
- در QA، ورود و مشاهده‌ی داشبورد برای مدیر، اپراتور، وکیل، تعمیرکار و مشتری موفق شد. مسیرهای نماینده‌ی معوقات، پرونده‌ی حقوقی و تعمیر دیده شدند. مسیر حقوقی مستقیم برای تعمیرکار رد شد.
- E2E تغییر رمز مشتری در کپی DB جداگانه انجام شد: پیام موفقیت رابط دیده شد؛ پس از خروج، PIN چهاررقمی قبلی رد و رمز شخصی وارد داشبورد شد. حساب‌های پایگاه نصب فعال و پایگاه اصلی QA دست‌نخورده ماندند.
- ارتقای E2E از بستهٔ core رسمی V4.0.2 به Candidate V4.0.3 روی clone تمیز موفق شد: updater تعداد ۹ فایل و یک migration را اعمال کرد؛ نسخهٔ برنامه 4.0.3 شد، migration اعمال شد و ورود مدیر/داشبورد پس از ارتقا باز شد.
- migration روی clone تمیز ۲۶۶ مشتری را در حالت PIN قرار داد و fingerprint جفت‌های شناسه/هش رمز پیش و پس از migration برابر ماند؛ هیچ هش موجودی بازنویسی نشد.
- روی clone جداگانه‌ای که از نصب محلی V4.0.2 ساخته شده بود، updater به‌درستی به‌دلیل تفاوت هش `database/proma-pay-install.sql` با baseline رسمی، پیش از نصب رد شد. پس از رد، ۸ فایل مقصدی که از قبل وجود داشتند با فایل‌های نصب فعال V4.0.2 برابر بودند و migration جدید همچنان وجود نداشت؛ نصب فعال تغییری نکرد.
- `tools/release-gate.php --local --static-only`: ۷۵۴ فایل PHP lint شد و تمام تست‌های ایستا/واحد تعریف‌شده در گیت موفق شدند. نتیجه‌ی ابزار: `RELEASE_GATE_LOCAL_STATIC_UNIT_PASSED_INTEGRATION_BLOCKED`.
- تست‌های هدفمند: `CustomerPasswordModeTest.php`، `CustomerCredentialPolicyTest.php` و `installment_settlement_engine_v150.php` پاس شدند.
- آزمون کنترل افزونه‌ها: پنج manifest و ۱۲۷ route شناسایی شدند؛ آزمون‌های ایستای release gate مربوط به accounting، repair، affiliate، sign-connect و Zarinpal پاس شدند.

## آزمون‌هایی که انجام نشدند

- فاز integration گیت اجرا نشد: گیت فقط اجرای مخرب را در `proma_qa_v204` با سه متغیر صریح می‌پذیرد؛ این دیتابیس موجود بازسازی یا به کار گرفته نشد.
- ۲۰ سناریوی مالی/حقوقی در fixture مستقل V4.0.3 به‌صورت کامل اجرا نشدند؛ فقط آزمون‌های واحد موجود و مورد پاداش حقوقی اجرا شدند.
- چرخه‌های ثبت پرداخت، refund/correction، webhook replay، دو پرداخت هم‌زمان، وصول اجرای حکم و مختومه‌سازی حقوقی روی DB جداگانه E2E نشدند.
- مرورگرهای Firefox و WebKit، آزمون keyboard/screen-reader و ماتریس کامل ۶ viewport برای Candidate حاضر اجرا نشد. گزارش QA قبلی اندازه‌های ۳۲۰ تا ۱۹۲۰ پیکسل را ثبت کرده است و به‌تنهایی مدرک V4.0.3 نیست.
- نصب تازهٔ Candidate روی پایگاه خالی اجرا نشد. ارتقا از مبنای رسمی V4.0.2 روی clone تمیز موفق شد؛ ارتقا روی clone منطبق با نصب محلی به‌علت اختلاف baseline در فایل نصب SQL عمداً رد شد و نیازمند تطبیق جداگانه است.

## سابقه‌ی آزمون‌های دستگاه

گزارش QA مورخ ۲۰۲۶-۱۰-۰۸ برای پنج نقش و ۱۵ اندازه‌ی صفحه (۳۲۰ تا ۱۹۲۰ پیکسل) نبود سرریز افقی را ثبت می‌کند. این شواهد از اجرای QA موجود است؛ آزمون screenshot-by-screenshot همه‌ی routeها و تمام نقش‌ها در این Candidate محسوب نمی‌شود.

## وضعیت

تست‌های ایستا/واحد پاس؛ E2E ارتقای baseline رسمی V4.0.2 و داشبورد پس از آن پاس؛ چند E2E خواندنی نقش‌ها و تغییر رمز مشتری روی DB موقت پاس؛ integration مالی/حقوقی و release gate کامل **اجرا نشده**. ارتقای clone مطابق نصب محلی به‌دلیل drift baseline حل‌نشده است. نسخه Production Ready نیست.
