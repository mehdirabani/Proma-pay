# تغییرات V4.0.4 — بازیابی بکاپ و ثبت پرداخت

- پس از بازیابی بکاپ‌های قدیمی، migrationهای سازگاری بررسی‌شده دوباره اجرا می‌شوند؛ ثبت موفق در تاریخچهٔ migration جای بررسی ساختار واقعی را نمی‌گیرد.
- ستون‌های نتیجهٔ درخواست پرداخت، صف رویدادها، محدودهٔ تخصیص و حالت رمز مشتری بررسی می‌شوند.
- جدول‌های موجود که در snapshot نیستند پاک می‌شوند تا سوابق جدید به شناسه‌های قدیمیِ بازیابی‌شده وصل نشوند. این رفتار مخصوص بازیابی کامل است.
- خطای SQL یا کپی فایل باعث بازگرداندن دیتابیس ایمنی و فایل‌های تغییرکرده می‌شود؛ فایل‌های جدید ایجادشده در تلاش ناموفق حذف می‌شوند.
- قفل نگهداری جلوی ورود درخواست‌های هم‌زمان حین بازیابی را می‌گیرد. قطع ناگهانی یا شکست recovery نشانگر نگهداری را باقی می‌گذارد.
- بکاپ InnoDB با snapshot مشترک و بکاپ دارای جدول MyISAM با قفل خواندن همهٔ جدول‌ها تهیه می‌شود.
- INSERTهای dump به‌صورت دسته‌ای commit می‌شوند و تنظیمات session دیتابیس پس از import برگردانده می‌شوند.
- تنظیمات کلید خارجی برای dumpهای استاندارد mysqldump که آن را داخل comment اجرایی می‌گذارند نیز صریحاً اعمال می‌شود؛ ترتیب تعریف جدول‌ها باعث خطای وابستگی نمی‌شود.
- درخواست پرداخت ناموفق با همان شناسه و اطلاعات، با compare-and-set قابل تلاش مجدد است؛ مبلغ یا ساعت متفاوت و کاربر متفاوت رد می‌شوند.
- اصلاحات V4.0.3 شامل حالت رمز شخصی مشتری و منع پاداش تسویه پس از ارجاع رسمی حقوقی حفظ شده‌اند.
