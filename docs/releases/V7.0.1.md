# Proma Pay V7.0.1 — Candidate

## Upgrade from V7.0.0

The in-app update targets the same V7.0.0 redesign archive previously provided (`v7.0.0-redesign-v2`). It contains changed Core runtime files and preserves `config/database.php`, installed plugins, storage, uploads, and customer data. The Core update has no new database migration. The single delivery ZIP also contains a fresh Core installer, the complete Core-plus-plugins package, and versioned standalone plugin packages.

- Core and displayed versions: `7.0.1` / `V7.0.1`; PWA manifest, Electron package metadata, and service-worker cache key are synchronized.
- Reference-led spacing adjustments cover the collections and credit-risk summaries, notification composer, and legal queue. Legal row actions use compact icon buttons.
- The collections legal-review count no longer binds a SQL parameter when no matching filter is present.
- Re-submitting a Bale account title reconfigures the existing unique account row and preserves event mappings. A changed token or bot ID requires a new successful connection check.
- Affiliate now installs without Accounting already active. Wallet-changing operations remain blocked until the Accounting ledger is active; they still cannot write unjournaled balance changes. Affiliate plugin package version is `1.1.0`; SignConnect is `1.2.8`.

## Candidate status

This is a candidate build, not a production-certified release. Local visual inspection covered the administrator notifications and legal pages; the collections and risk pages were previously inspected after their fixes. PHP syntax checks were run on touched PHP files. Automated application, database, migration, role-session, and external-provider test suites were not run. Archive manifests and checksums are verified during packaging.
