# Proma Pay V7.0.0 — Candidate

## Design and product scope

- Added a shared V7 visual layer for the responsive shell, headings, cards, filters, tables, and tabs. Contract lists now surface total and page-level collection summaries; contract detail tabs keep their own content panels isolated. Installment and overdue queues use compact status tabs, filter cards, and phone layouts. The collections center groups operator tasks and collection queues in a responsive operations board.
- Refreshed the credit-risk customer list with page-level score summaries, search, pagination, responsive customer cards, and explicit handling of customers without a saved score.
- Added legal queue summary counts and separate pending review counts for identity documents and payment receipts. Existing tabs continue to show only the selected review category.
- Reworked the notifications page into an inbox and delivery/settings workspace; administrators retain the role-targeted announcement composer and delivery history. Chat now uses a responsive contact, conversation, and profile layout, with the profile fields fetched through an explicit allowlist.
- Rebuilt the operator dashboard around assigned overdue installments, upcoming follow-ups, and its contract queue; the lawyer dashboard around active legal cases, eligible referrals, and case expenses; and the customer dashboard around the next due installment, open balance, and recent payments. The repair-technician portal now prioritizes the technician's assigned repair queue, ready-for-delivery devices, and expense requests, while keeping manager-only financial and assignment controls out of the technician view.

## PromaSignConnect 1.2.7

- When a production Bale provider row with the requested title is archived, saving from the add form restores the same row, preserving provider event mappings. The restored row is inactive and requires a fresh connection test.
- If the title belongs to an active row, the form returns a clear instruction to edit that row instead of silently overwriting its token, state, or mappings.
- A rare unique-key race is translated into a clear application message instead of exposing SQLSTATE 23000 / MySQL 1062.
- No schema migration is required for this fix; the unique key remains in place.

## PromaAffiliate 1.0.9 and PromaRepair 1.2.12

- Fixed plugin migration execution for MySQL SQL-level `PREPARE`, `EXECUTE`, and `DEALLOCATE PREPARE` statements. Affiliate wallet migration `2026_10_05_affiliate_wallet_management.sql` uses these commands to add optional payout fields without duplicating existing columns; the executor now routes these statements through `PDO::exec`, which allows new installs and retries after an interrupted migration to continue.
- Redesigned the repair-technician home page around assigned work, ready-for-delivery devices, and technician expense requests.

## Package status

This is a candidate build. Application, browser, database, and external-provider test suites were not run for this candidate. The packaging scripts verify archive manifests and file checksums; this verifies package integrity only. Production availability and operational compatibility are not certified. The affiliate plugin still requires the PromaAccounting plugin to be installed and active before it can be installed or activated.

The plugin API remains 1.1 and plugin minimum Core requirements remain at 6.0.2 to allow the candidate plugin packages to upgrade existing installations. PromaSignConnect retains its declared tested maximum of 6.0.2 because V7 integration has not been tested.
