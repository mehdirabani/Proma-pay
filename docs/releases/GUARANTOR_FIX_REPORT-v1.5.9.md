# Guarantor Document Fix Report — V1.5.9

## مسئلهٔ ریشه‌ای

سامانه دو منبع معتبر اما متفاوت برای ضامن داشت:

1. `contract_guarantors` برای ضامن‌های انتخاب‌شده از فهرست موجود.
2. `contract_guarantor_people` برای ضامن‌های دستی وابسته به قرارداد.

مسیر تولید متن قرارداد فقط منبع دوم را می‌خواند. بنابراین قراردادهایی که صرفاً ضامن موجود داشتند، در پیش‌نمایش یا چاپ بخش ضامن و محل امضا را ناقص نشان می‌دادند. مشکل، CSS یا قالب چاپ نبود و مخفی‌کردن آن در رابط کاربری راه‌حل محسوب نمی‌شد.

## اصلاح پیاده‌سازی‌شده

- `ContractDocument::guarantorsForDocument()` هر دو منبع را با ترتیب پایدار ادغام و بر پایهٔ شناسه از تکرار جلوگیری می‌کند.
- `contract_guarantor_snapshots` مشخصات ضامن انتخاب‌شده را در زمان ذخیرهٔ قرارداد ثبت می‌کند تا تغییرات بعدی پروفایل تاریخی قرارداد را تغییر ندهد.
- migration `2026_09_06_contract_guarantor_snapshots.sql` جدول، ایندکس و backfill دادهٔ تاریخی را فراهم می‌کند.
- `ContractDocument::viewModel()` تنها مرجع preview و print است؛ کنترلر جزئیات و `printDocument()` دیگر مدل‌های متفاوت نمی‌سازند.
- placeholders `{{guarantors_section}}` و `{{signature_section}}` از همان مجموعه ضامن نهایی پر می‌شوند.

## رفتار مورد انتظار

- قرارداد قدیمی با ضامن انتخابی، پس از migration مشخصات snapshot خود را نشان می‌دهد.
- قرارداد جدید، مشخصات ضامن را هنگام پیوند ثبت می‌کند.
- ضامن دستی همچنان پشتیبانی می‌شود و کنار ضامن‌های انتخابی نمایش می‌یابد.
- تغییر نام بعدی ضامن، خروجی قراردادهای پیشین را تغییر نمی‌دهد.
- تعداد امضاهای ضامن برابر تعداد ضامن‌های نهایی قرارداد است.

## اعتبارسنجی

آزمون استاتیک ساختار read-model و migration را بررسی می‌کند. آزمون MariaDB با دادهٔ واقعی QA، ضامن انتخابی، تغییر نام تاریخی، ایجاد قرارداد دوم، ضامن دستی، preview و print را اجرا کرده و با نتیجهٔ `INTEGRATION_GUARANTOR_DOCUMENT_V159_OK` عبور کرده است.

## سازگاری و ایمنی

این اصلاح فقط دادهٔ snapshot جدید و قابل بازسازی را اضافه می‌کند؛ پرداخت‌ها، اقساط، اسناد مالی، نقش‌ها، فایل‌های بارگذاری‌شده و پیکربندی database را تغییر نمی‌دهد. migration فقط توسط updater کنترل‌شده اجرا می‌شود و هیچ DDL در درخواست‌های عادی صفحه انجام نمی‌شود.
