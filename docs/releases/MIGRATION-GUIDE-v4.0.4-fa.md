# راهنمای V4.0.4

## ارتقا

بستهٔ تفاضلی متناسب با نسخهٔ مبنا را در بخش بروزرسانی نصب کنید. برای V4.0.2 و V4.0.3 بسته‌های جداگانه ارائه می‌شود. اگر هش فایل فعلی با مبنا تفاوت داشته باشد، نصب متوقف می‌شود؛ تغییرات محلی باید بررسی شوند.

## بازیابی بکاپ قدیمی

در تنظیمات ← بکاپ، فایل ZIP یا SQL کامل پروما پی را انتخاب و عدد تایید همان فرم را وارد کنید. بکاپ ایمنی پیش از هر بازیابی ساخته می‌شود. تنظیمات اتصال دیتابیس و سورس برنامه از بکاپ قدیمی جایگزین نمی‌شوند. فایل‌های کاربران و داده‌های storage با استثنای cache، session، log، updates و backups بازیابی می‌شوند. فایل‌های موجود خارج از آرشیو باقی می‌مانند؛ این نسخه پاکسازی سراسری uploads انجام نمی‌دهد.

پشتیبانی عملی روی بکاپ واقعی `proma-pay-backup-2026-10-06-08-05.zip` بررسی شده است. dump ناقص یا شامل انتقال به دیتابیس دیگر رد می‌شود. برای بکاپ‌های بسیار قدیمی با ساختار متفاوت، عدم سازگاری باید به بازگشت ایمنی منجر شود؛ سازگاری همهٔ تاریخچه‌ها ادعا نمی‌شود.

## قطع برق یا شکست بازگردانی ایمنی

نشانگر `storage/.runtime-lock/restore-pending.json` نام بکاپ ایمنی را نگه می‌دارد و درخواست‌های برنامه با 503 متوقف می‌شوند. ابتدا بکاپ ایمنی را توسط ابزار MySQL و فایل‌های ایمنی را با استفاده از `storage/.restore-work/` بازیابی کنید؛ فقط پس از تایید دیتابیس و فایل‌ها نشانگر را حذف کنید. بکاپ ایمنی و journal را تا پایان بازیابی نگه دارید. قفل فایل فقط پردازش‌های استفاده‌کننده از bootstrap همین نصب را هماهنگ می‌کند؛ اتصال مستقیم ابزارهای دیگر به دیتابیس باید هنگام restore متوقف باشد.

## محدودیت‌ها

بازیابی کامل نیازمند اجازهٔ CREATE/DROP/ALTER و برای snapshot دارای MyISAM نیازمند LOCK TABLES است. فضای کافی برای بکاپ ایمنی و journal لازم است. ZIP/SQL خراب، کمبود فضا یا دسترسی ناکافی باید به خطا و حفظ بکاپ ایمنی منجر شود. این نسخه بررسی جامع همهٔ مسائل حقوقی، وفاداری و بار هم‌زمانِ مأموریت گسترده را جایگزین نمی‌کند.
