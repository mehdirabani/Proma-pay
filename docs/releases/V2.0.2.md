# Proma Pay 2.0.2

Patch release for installations on Proma Pay 2.0.1. The full Core archive is a complete installer; the separate Update archive is differential and targets the verified 2.0.1 Core archive.

## Changes

- Reworked the shared workspace shell and role dashboards with a consistent responsive navigation, clearer page hierarchy, more legible summary cards, and improved spacing across desktop and mobile breakpoints.
- Removed the oversized desktop navigation close glyph; the close control is only available in the mobile navigation state.
- Corrected contract-detail tab ownership so each panel belongs to one tab, including summary, installments, payments, settlement, legal, files and activity. Header quick actions now activate the relevant tab rather than pointing at an inactive anchor.
- Kept installment actions and payment details in a responsive single-column workspace on narrow screens; removed the need to horizontally scroll the installment list to reach actions.
- Creating or updating a contract with a new guarantor now creates (or reuses, after strict identity matching) an active customer account in the same contract transaction. Existing customer passwords are not reset; newly created account login remains compatible with the last-four-mobile rule. Contract printing deduplicates account links and historical guarantor snapshots.
- Replaced Quill's CSP-blocked inline whitespace style with a stylesheet class; no CSP policy relaxation was introduced.
- Invalidated asset and service-worker cache versions for 2.0.2.

## Install

For an existing 2.0.1 installation, use `PromaPay-Update-v2.0.2.zip` through Settings → Update. Keep a database and file backup first. Use `PromaPay-v2.0.2.zip` only for a new installation or a controlled full reinstall. Do not upload the full installer as an update package.

Local PHP lint, the configured static/unit and MariaDB integration gates, role HTTP smoke tests, real-browser responsive/tab checks, package extraction and archive verification are recorded in `FULL_TEST_REPORT-v2.0.2.md`. Local QA is not a certification of the customer’s production hosting environment.
