# Proma Pay V4.0.1

V4.0.1 is a local QA candidate based on the existing V4.0.0 Core archive. It contains the customer mobile-PIN login fix, plugin provider lifecycle repair, and the tested V4 installment and repair flows.

## Changes

- Customer accounts can sign in with the four-digit suffix of their registered mobile number, including Persian or Arabic numerals. The server validates this policy without replacing existing customer hashes during login.
- Plugin install and health checks now load providers through their registration lifecycle. This makes plugin-owned autoloaders available when Affiliate runs its install-time health check.
- PromaRepair 1.2.6 installs and reports healthy in the isolated QA copy. Technician dashboard, orders, requests, expenses, history, and profile pages render without HTTP 500 errors.
- Repair device-secret reveal is one-time, session-bound, and audited; the tested synthetic QA value was removed and the original encrypted value restored.
- The V4 installment quick-payment modal and the partial-payment tab render their contract and installment results.

## Delivery

- PromaPay-v4.0.1.zip: Core installer.
- PromaPay-Update-v4.0.1.zip: differential update from the verified V4.0.0 Core archive.
- PromaAffiliate-v1.0.5.zip: optional plugin package for Affiliate; Accounting must be active at a compatible version first.
- PromaRepair 1.2.6 remains a separately installed optional plugin.

The local static/unit gate and disposable QA login sweep are recorded in the test report. Destructive release integration tests and production availability certification were not run for this candidate.
