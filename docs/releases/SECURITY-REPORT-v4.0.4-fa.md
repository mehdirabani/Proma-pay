# بررسی امنیت V4.0.4

- تایید عدد فرم، POST، CSRF و نقش admin برای restore حفظ شده‌اند.
- dump ناقص، دستورات خارج از محدودهٔ نوع بکاپ و جدول‌های qualified به دیتابیس دیگر رد می‌شوند.
- مسیر traversal در ZIP رد می‌شود؛ symlink مقصد و خروج از محدودهٔ پوشه مجاز پذیرفته نمی‌شوند.
- runtime lock و journal خصوصی از بکاپ/restore فایل‌ها مستثنا هستند؛ sessions، logs و cache نیز از ZIP قدیمی جایگزین نمی‌شوند.
- retry درخواست پرداخت به مالک قبلی مقید است و compare-and-set جلوی مالکیت هم‌زمان همان retry را می‌گیرد.
- رمزهای موجود در ارتقا/restore بازنویسی نشدند. حالت رمز شخصی V4.0.3 حفظ شده است.

این گزارش ممیزی محدود به تغییرات نسخه و آزمون‌های ثبت‌شده است؛ ممیزی امنیت مستقل کامل ادعا نمی‌شود.
