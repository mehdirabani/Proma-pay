# ساختار پوشه‌های پروژه

این راهنما مسیرهای اصلی سورس و داده‌های محلی را مشخص می‌کند. جزئیات بسته‌بندی نسخه‌ها در `docs/releases/ARTIFACT_LAYOUT.md` نگهداری می‌شود.

## سورس و اجزای سامانه

- `core/`, `controllers/`, `models/`, `helpers/`, `services/`, `views/`: هسته و منطق برنامه PHP.
- `plugins/`: افزونه‌های مستقل سامانه و قراردادهای اتصال آن‌ها به Core.
- `database/`: schema، migration و ابزارهای پایگاه‌داده.
- `assets/`, `html/`: دارایی‌های رابط کاربری و منابع وب.
- `scripts/`, `tools/`, `tests/`: ساخت، کنترل کیفیت و آزمون.
- `electron/`: پوسته و ابزارهای دسکتاپ.
- `docs/`: مستندات معماری، عملیات، استقرار، نسخه‌ها و ممیزی.

## خروجی‌ها و داده‌های محلی

- `dist/`: خروجی‌های قابل‌بازسازی؛ بسته‌ها طبق دسته و نسخه در مسیرهای ثابت مستندشده نگهداری می‌شوند.
- `output/`: آرشیو محلی و خارج از Git برای گزارش‌های QA و داده‌های ابزارهای توسعه.
  - `output/qa/`: گزارش‌های اجرای release gate و آزمون‌های محلی.
  - `output/playwright/cli-captures/`: snapshotهای مرورگر با شناسهٔ بازه یا تاریخ.
  - `output/analysis-cache/`: cacheهای تحلیل ایستا و نمودار وابستگی.
  - `output/security-audit/<date>/`: telemetry و خروجی ممیزی امنیتی.
- `storage/`: داده‌های runtime، گزارش، پایگاه‌داده و QA محلی؛ نباید وارد Git شوند.
  - `storage/testing/releases/<version>/` و `storage/testing/plugins/`: snapshotهای محلی و بسته‌های QA، دسته‌بندی‌شده بر اساس نسخه و نوع.
- `tmp/updates/<from>-to-<to>/`: cloneها و خروجی‌های موقت آزمون به‌روزرسانی.
- `backups/`: snapshotهای محلی برای بازیابی؛ خارج از نسخه‌بندی Git.
- `tmp/`: فایل‌های گذرا و محیط‌های موقت آزمون.
- `node_modules/` و `vendor/`: وابستگی‌های نصب‌شده.

برای افزودن فایل به مخزن، ابتدا مشخص کنید که فایل سورس، تست یا مستندات پایدار است؛ داده‌ی runtime، backup، بسته‌ی build و خروجی آزمون در Git ثبت نمی‌شود.
