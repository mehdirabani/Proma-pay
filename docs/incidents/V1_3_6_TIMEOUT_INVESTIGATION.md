# بررسی اتصال متناوب V1.3.6

## تفکیک خطا

`ERR_CONNECTION_TIMED_OUT` پیش از رسیدن درخواست به PHP رخ می‌دهد و با صفحه خطای PHP قابل حل نیست. HTTP 500 نیز مسئله‌ای جداگانه در سطح برنامه است.

## مشاهدهٔ مستقل در 2026-07-18

- DNS رکورد `A`: `185.78.22.44`
- DNS رکورد `AAAA`: ندارد
- درخواست IPv4 به صفحه ورود: `HTTP 200`
- زمان کل نمونه‌برداری IPv4: حدود `0.35s`
- IPv6: ناموفق به علت نبود رکورد AAAA، نه پاسخ HTTP برنامه

نتیجه: در این نقطه و در همان لحظه timeout بازتولید نشد. این مشاهده به تنهایی سلامت ISP، مودم، WAF یا فایروال هاست را اثبات نمی‌کند.

## اقدام لازم در هاست

1. هنگام رخداد، timestamp، IP عمومی پیش و پس از restart مودم و `X-Request-ID` هر پاسخ HTTP را ثبت کنید.
2. مدیر هاست همان بازه را در web server، PHP-FPM، MariaDB، ModSecurity، CSF/LFD، Fail2ban و WAF بررسی کند.
3. محدودیت connection، worker، CPU، RAM، disk و inode بررسی شود.
4. هیچ ISP یا subnet به‌صورت کلی whitelist و هیچ WAF یا فایروالی به‌صورت سراسری غیرفعال نشود.
5. `/health/live` و `/health/ready` از دو شبکه مستقل و یک مانیتور بیرونی پایش شود.

## بهبودهای Core

- `/health/live`: بدون دیتابیس، session و plugin.
- `/health/ready`: پایگاه داده، storage و فایل‌های اصلی را بررسی و در عدم آمادگی `503` برمی‌گرداند.
- صفحه‌های static برای خطاهای زیرساختی 400، 403، 404، 429، 500، 502، 503 و 504 افزوده شده‌اند.
