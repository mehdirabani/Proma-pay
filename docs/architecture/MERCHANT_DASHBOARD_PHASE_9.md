# پنل فروشنده و گزارش‌ها — فاز ۹

## مسیر و دسترسی

صفحهٔ خواندنی پنل در مسیر `/merchant-portal` قرار دارد. کاربر باید نشست معتبر و عضویت فعال در فروشندهٔ فعال داشته باشد. همهٔ خواندن‌ها بر اساس `merchant_id` محدود می‌شوند. جابه‌جایی فروشنده فقط از میان عضویت‌های همان کاربر ممکن است. نقش‌های فاقد `settlement.read` تعداد و وضعیت را می‌بینند، اما مبلغ مطالبه، چک و تعهد تسویه در پاسخ HTML آن‌ها قرار نمی‌گیرد.

## بخش‌های پنل

- سفارش‌های اقساطی، درخواست‌های معلق و تعداد قراردادهای واقعیِ فعالِ پیوندخورده.
- فهرست وضعیت چک صیادی با نمایش تاریخ اولین قسط و سررسید چک برای مقایسه.
- تعهدها و گزارش خالص تسویه به تفکیک وضعیت، موعد و وجود منبع مالی ثبت‌شده.
- وضعیت reconciliation و مغایرت صورت‌حساب.
- وضعیت تحویل webhook، تلاش‌ها، HTTP و کد خطا، بدون نمایش response/payload.
- تاریخچهٔ رویدادهای API بدون metadata حساس.

## مرزبندی مالی

وضعیت `paid` در دفتر تسویه جدا از `pending/eligible/scheduled/processing` نمایش داده می‌شود. `gross_receivable_toman` با برچسب «مطالبهٔ ثبت‌شده، وجه نقد نیست» ارائه می‌شود. وجود حساب تأمین مالی صرفاً به‌عنوان فیلد ثبت‌شده گزارش می‌شود و به‌تنهایی اثبات وجه نقد یا پرداخت بانکی نیست. پنل عملیات ایجاد/تأیید/پرداخت/اصلاح تسویه یا ثبت چک انجام نمی‌دهد.

## آزمون‌ها

- `tests/static_merchant_dashboard_phase9.php`: دسترسی، فیلتر tenant، حداقل‌سازی داده و برچسب‌های مالی.
- `tests/merchant_dashboard_phase9.php`: آزمون روی پایگاه‌داده disposable برای جداسازی عضویت و محدودیت نقش‌ها.
- آزمون‌های موجود Phase 2 تا 8 همچنان در release gate محلی اجرا می‌شوند.

## مرز انتشار

پنل فعلی گزارش‌محور است. گردش کار بررسی درخواست، پیوند دستی مشتری/قرارداد، ثبت تضمین، تعیین مالکیت مطالبات و عملیات پرداخت باید با کنترل‌های مجوز و مدارک مالی/حقوقی جداگانه تکمیل شود. هیچ مرحله‌ای از این صفحه تعهد نقدینگی را خودکار تأیید نمی‌کند.
