# هسته چندفروشندگی — فاز ۲

## دامنه

این فاز زیرساخت داده‌ای فروشندگان، سایت‌ها، اتصال‌های API، اعضای فروشنده، اعتبارنامه‌های آزمایشی، نسخه‌های سیاست و رویدادهای ممیزی را اضافه می‌کند. مسیر فروش مستقیم و جدول‌های قرارداد، اقساط، پرداخت و دفترکل را تغییر نمی‌دهد.

## مدل داده

- `merchant_accounts` حساب فروشنده را نگه می‌دارد. فروشنده تازه با وضعیت `pending` ساخته می‌شود.
- `merchant_sites` دامنه‌ی HTTPS ثبت‌شده‌ی هر فروشنده را نگه می‌دارد. دامنه تا زمان تأیید در دسترس API نیست.
- `merchant_connections` اتصال مستقل یک سایت را نگه می‌دارد. اتصال با وضعیت `inactive` و کلید قطع اضطراری خاموش ساخته می‌شود.
- `merchant_memberships` عضویت کاربر در فروشنده را با نقش ثابت سمت سرور ثبت می‌کند. دعوت اولیه تا پذیرش، فعال نمی‌شود.
- `merchant_api_credentials` فقط SHA-256 خامِ ۳۲ بایتی توکن را ذخیره می‌کند. توکن فقط هنگام صدور آزمایشی یک‌بار نمایش داده می‌شود؛ صدور زنده تا تأییدهای فاز ۵ مسدود است.
- `merchant_policy_versions` نسخه‌ی تغییرناپذیر سیاست را با JSON کانونی و هش محتوا نگه می‌دارد. نسخه‌ی تازه `draft` است.
- `merchant_policy_heads` نسخه‌ی منتخب هر نوع سیاست را برای هر اتصال تعیین می‌کند. کلید خارجی مرکب جلوی اشاره به نسخه‌ی اتصال یا نوع سیاست دیگری را می‌گیرد.
- `merchant_audit_events` رویدادهای فروشنده را با فراداده‌ی محدود ثبت می‌کند و نام فیلدها و مقادیر توکن خام را رد می‌کند.

## مرزبندی دسترسی

خواندن‌های API تنها با سه‌تایی فروشنده، سایت و اتصال موجود در `MerchantAccessContext` انجام می‌شوند. اعتبارنامه، اتصال فعال، سایت تأییدشده، فروشنده فعال و نبود قطع اضطراری هم‌زمان لازم‌اند. مجوزها دقیق و بدون wildcard هستند. عضویت‌های پنل نیز از نگاشت نقش ثابت استفاده می‌کنند و دسترسی تأیید تسویه به‌طور پیش‌فرض داده نشده است.

Migration در `database/migrations/2026_10_23_multi_merchant_core_phase2.sql` افزایشی است و همان جداول برای نصب تازه در `database/proma-pay-install.sql` تعریف شده‌اند. کلیدهای خارجی مرکب، مالکیت اتصال بر سایت را در دیتابیس enforce می‌کنند.

## آزمون و محدودیت این فاز

تست‌های مستقل در `tests/merchant_core_phase2.php` و `tests/static_multi_merchant_core_phase2.php` به release gate افزوده شده‌اند. تست‌های داده‌پایه باید فقط روی یک دیتابیس دورریختنی و اختصاصی اجرا شوند. در زمان پیاده‌سازی، تنظیمات `PROMA_TEST_DB_*` در دسترس نبود؛ بنابراین اعمال Migration روی MySQL/MariaDB و آزمون تراکنش، قفل هم‌زمانی و کلیدهای خارجی هنوز تأیید نشده است. این فاز به‌تنهایی API عمومی یا مسیر فعال‌سازی اتصال را عرضه نمی‌کند و Production Ready نیست.
