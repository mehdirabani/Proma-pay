# Proma Pay V1.4.5 - Final QA Report

تاریخ اجرا: ۱۴۰۵/۰۵/۰۲

وضعیت: موفق در محیط QA محلی؛ لایه فایروال و blacklist شبکه تولید فقط با لاگ هاست قابل گواهی است.

## دامنه بررسی

- routeهای خنثی و سازگاری endpointهای قدیمی
- فشار polling چت و اعلان‌ها، timeout، backoff و هماهنگی چند تب
- محدودیت batch پیام‌ها و حذف queryهای unread غیرضروری
- صفحات تأیید اصلاح مشخصات و سلامت سامانه
- probeهای مستقل فایل استاتیک، PHP و دیتابیس
- مودال‌های موبایل، visual viewport و صفحه‌کلید نرم‌افزاری
- نصب بروزرسانی از نسخه‌های ۱.۴.۲، ۱.۴.۳ و ۱.۴.۴
- بسته کامل، بسته بروزرسانی، manifest و افزونه حسابداری

## نتایج UI و رسپانسیو

- صفحه تأیید اصلاح مشخصات در عرض‌های ۱۴۴۰ و ۳۹۰ پیکسل بدون اسکرول افقی و تداخل هدر بررسی شد.
- صفحه سلامت سامانه در عرض‌های ۱۴۴۰ و ۳۹۰ پیکسل بدون اسکرول افقی بررسی شد.
- ۱۸۳ حالت مودال در مسیرهای قرارداد، جزئیات قرارداد، کاربران، مشتریان، تنظیمات، مدال‌ها، تقویم و مدیریت فایل بررسی شد.
- آزمون مودال‌ها در اندازه‌های ۳۲۰×۵۶۸، ۳۶۰×۶۴۰ و ۳۹۰×۸۴۴ اجرا شد.
- هیچ شکست در containment، اسکرول افقی، نمایش header/footer، ارتفاع کنترل یا جای‌گیری label ثبت نشد.
- مودال افزودن قسط در عرض ۳۲۰ پیکسل دارای ورودی‌های ۴۴ پیکسلی، textarea طبیعی و اسکرول مستقل بدنه است.

## نتایج شبکه و کارایی

- PHP lint برای ۲۹۷ فایل بدون خطا انجام شد.
- همه تست‌های static، امنیت، شبکه، هسته، زرین‌پال و افزونه حسابداری موفق بودند.
- تست HTTP نقش‌های مدیریت، اپراتور، وکیل و مشتری و کنترل دسترسی ممنوع موفق بود.
- هم‌پوشانی دو worker نشست در آزمون هم‌زمانی حدود ۴۸۴٫۹۶ میلی‌ثانیه ثبت شد.
- صدک ۹۵ دیتابیس داشبورد حسابداری حدود ۴٫۵۷ میلی‌ثانیه و صدک ۹۵ HTTP آن حدود ۷۸٫۷۹ میلی‌ثانیه بود.
- polling چت دارای interval پایه ۱۵ ثانیه، backoff تا ۱۸۰ ثانیه و lease میان تب‌ها است.
- polling اعلان‌ها دارای interval پایه ۴۵ ثانیه، backoff تا ۳۰۰ ثانیه و lease میان تب‌ها است.
- پاسخ fetch چت شمارش unread اجرا نمی‌کند و UPDATE خوانده‌شدن فقط برای batch غیرخالی انجام می‌شود.
- تاریخچه اولیه و batchهای polling هر کدام حداکثر ۱۰۰ پیام دارند.
- تمام form actionهای تولیدشده برای عملیات حذف از واژه‌های پرریسک WAF پاک شدند.
- route خنثی `users/retire/0` با session و CSRF واقعی به handler قدیمی نگاشت شد و پاسخ redirect معتبر داد.

## نتایج سلامت و بروزرسانی

- `/health-static.txt` در QA پاسخ ۲۰۰ و محتوای `proma-static-ok` برگرداند.
- `/health/live` در QA پاسخ ۲۰۰ و JSON معتبر برگرداند.
- صفحه سلامت سامانه مسیر تشخیص جداگانه برای شبکه/WAF، PHP worker و دیتابیس نمایش می‌دهد.
- بسته هم‌نسخه، قدیمی و ناسازگار پیش از نوشتن فایل و اجرای migration رد می‌شود.
- migration اصلاح‌شده V1.4.3 فاقد دستور حذف داده است و در بسته ارتقا باقی مانده است.
- manifest بروزرسانی از داده‌های عملیاتی `config/database.php`، افزونه‌ها، storage و uploads محافظت می‌کند.
- ارتقای واقعی یک استخراج پاک از commit نسخه V1.4.3 روی دیتابیس ایزوله به V1.4.5 موفق بود.
- در ارتقای واقعی نهایی ۶۲ فایل نصب و هر ۶ migration با وضعیت `success` ثبت شدند.
- پیش از ارتقا بکاپ ایمنی ZIP معتبر با حجم ۲۸۶۵۳۰ بایت ساخته شد، probe استاتیک نیز نصب شد و نسخه فایل‌ها پس از نصب `V1.4.5` بود.

## محدودیت محیط تولید

خطای `ERR_CONNECTION_TIMED_OUT` که با تغییر IP برطرف می‌شود پاسخ HTTP ندارد و در لایه‌ای پیش از PHP رخ می‌دهد. برنامه می‌تواند فشار و الگوهای محرک را حذف کند و probe تشخیصی بدهد، اما مشاهده و آزادسازی IP در CSF/LFD، ModSecurity، WAF یا فایروال فقط در اختیار مدیر هاست است.
