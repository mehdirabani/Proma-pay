# Proma Pay V1.4.8 - Final QA Report

وضعیت: گیت انتشار محلی و بررسی مستقل آرشیو با موفقیت انجام شد.

## مسئلهٔ عملیاتی

سرویس اشتراکی گزارش کرد که یک IP در هر ثانیه تعداد زیادی درخواست فرستاده و توسط لایهٔ امنیتی موقتاً مسدود شده است. صرفاً سریع‌تر کردن queryهای SQL برای این مسئله کافی نیست؛ سامانه باید پیش از ایجاد session و query بتواند burst درخواست را قطع کند و مرورگر نیز نباید به علت poll، خطای 429 یا handler تکراری درخواست انباشته بسازد.

## کنترل‌های V1.4.8

- `RequestFloodGuard` قبل از `Auth::start()` اجرا می‌شود، با token bucket فایل‌محور و `flock` هماهنگ است و برای اجرا به MySQL نیاز ندارد.
- IP فقط از `REMOTE_ADDR` گرفته می‌شود؛ هدرهای forwarded غیرقابل اعتماد نیستند تا کاربر نتواند با جعل header محدودیت را دور بزند.
- بودجهٔ سراسری درخواست پویا، بودجهٔ جدا برای chat poll، notification poll و health، و پاسخ 429 دارای `Retry-After` بررسی شد.
- در JavaScript، همهٔ fetchهای برنامه از صف فاصله‌دار عبور می‌کنند. پاسخ 429 زمان توقف سراسری همان تب را ثبت می‌کند و poller بعد از شکست backoff می‌گیرد.
- بازهٔ poll گفت‌وگو، اعلان و حالت تب پنهان افزایش یافت؛ lease میان تب‌ها نیز حفظ شد تا چند تب یک کاربر درخواست موازی تولید نکنند.
- قوانین cache برای CSS، JavaScript، فونت و تصویر با URL نسخه‌دار اضافه شد. مسیرهای پویا و health probe از این cache مستثنی هستند.
- سازندهٔ انتشار aliasهای قدیمی `proma-pay_vX-Y-Z.zip` و `proma-update_vX-Y-Z.zip` را قبل از بسته‌بندی حذف می‌کند و verifier نبودن آن‌ها را الزام می‌کند.

## آزمون‌ها

- lint تمام فایل‌های PHP در گیت انتشار.
- آزمون مستقل `request_flood_guard_v148.php`: ظرفیت اولیه، رد burst با retry interval، refill زمانی و بودجهٔ جداگانهٔ chat poll.
- تست‌های static، امنیت، session، دیتابیس، نقش‌ها، مودال‌ها، بستهٔ بروزرسانی و افزونه‌های حسابداری و زرین‌پال.
- تست HTTP تکرارشوندهٔ داشبورد حسابداری و تست degraded mode افزونه.
- باز کردن آرشیوهای core، update و افزونه، بررسی checksum، manifest، مسیرهای امن، lint محتویات ZIP و نبود aliasهای تکراری.

## نتیجهٔ عملیاتی

کاربر معمولی می‌تواند در یک تب درخواست‌های تعاملی خود را انجام دهد، اما یک حلقهٔ refresh، افزونهٔ خراب یا poller تکراری پیش از فشار آوردن به PHP و MySQL با HTTP 429 متوقف می‌شود. از طرف دیگر cache دارایی‌ها تعداد درخواست‌های استاتیک را پس از نخستین بارگیری به شکل چشمگیر کم می‌کند. این لایه جایگزین بررسی امنیت سیستم کاربر نیست؛ اگر بدون باز بودن سامانه همان IP ترافیک غیرعادی ایجاد کند، تشخیص بدافزار یا افزونهٔ مرورگر همچنان بر عهدهٔ کاربر و سرویس‌دهنده است.
