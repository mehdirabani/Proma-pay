# نتایج QA نسخهٔ Proma Pay V4.0.0

**محیط:** Laragon، PHP 8.3.33، MySQL 8.4.3، ویندوز  
**نتیجهٔ گیت:** `RELEASE_GATE_LOCAL_QA_OK_NOT_PRODUCTION_CERTIFIED`

## آزمون نصب تمیز و اجزای سامانه

- lint موفق برای ۷۴۵ فایل PHP.
- همهٔ آزمون‌های پیکربندی‌شدهٔ static، unit، امنیت، به‌روزرسانی، پایگاه‌داده، HTTP، افزونه، مالی و کارایی در `tools/release-gate.php --local` موفق شدند.
- آزمون‌های HTTP نقش‌های مدیر، اپراتور، وکیل و مشتری و مسیرهای مجاز/غیرمجاز موفق شدند.
- آزمون استایل/اسکریپت مودال، داشبورد حسابداری، فایل‌ها، پرداخت، تسویه، صورتحساب حقوقی، outbox، سهمیهٔ درخواست، بازیابی migration و افزونهٔ تعمیرات موفق شدند.
- آزمون رگرسیون مسیر stale افزونه نشان داد افزونهٔ فعال پس از انتقال/بازیابی، مسیر فایل‌های نصب جاری را پیدا می‌کند.
- بررسی آرشیو Core، Update و Accounting موفق شد؛ syntax تمام ۸٬۱۳۴ فایل PHP آرشیو Core و فایل‌های PHP بسته‌های افزونه/Update نیز تایید شد.
- بستهٔ مستقل PromaRepair نسخهٔ ۱.۲.۶ ساخته شد و هش فایل‌های داخل ZIP با manifest بسته تطبیق داده شد.

## بکاپ ارسالی

- فایل ZIP بکاپ در پایگاه‌دادهٔ جداگانه بازیابی و مهاجرت V4 روی کپی آزمون اجرا شد؛ پایگاه‌دادهٔ اصلی و فایل ZIP دست‌نخورده ماندند.
- شمار رکوردهای کپی ارتقایافته: ۲۷۱ حساب، ۲۹۱ قرارداد، ۷۲۳ پرداخت و ۱٬۰۹۱ قسط؛ شمارها پس از migration ثابت ماند.
- ورود HTTP تک‌به‌تک برای ۲۷۱ حساب آزمایش شد. پس از ارتقای افزونهٔ تعمیرات از ۱.۲.۳ به ۱.۲.۵، تعداد ۲۶۸ حساب فعال وارد شدند؛ ۳ حساب غیرفعال طبق انتظار رد شدند.
- نام کاربری، هش رمز و زمان آخرین ورود هر ۲۷۱ حساب پس از آزمون با مقادیر اولیه تطبیق داده شد.

## اصلاح‌های تاییدشده

- ردکردن رمز کوتاه مشتری در ورود و الزام حداقل ۸ نویسه.
- استفاده از نام مستعار quoted برای `manual` در خلاصهٔ مدال‌های MySQL.
- ترمیم مسیر محلی افزونهٔ فعال در زمان بوت پس از انتقال بکاپ.
- اصلاح مرجع namespace در داشبورد تعمیرکار؛ این اصلاح همراه PromaRepair نسخهٔ ۱.۲.۶ به‌صورت بستهٔ جداگانه تحویل می‌شود.
- سازگارسازی migrationهای schema repair و قانونی با MySQL 8.4.

## محدودیت‌های نتیجه

- گیت Production/availability اجرا نشده است؛ نسخه Candidate محلی است.
- این QA بسته را در نصب فعال کاربر نصب نکرد؛ برای نصب در Apache لارگون، `ZipArchive` باید در همان PHP فعال باشد و Apache پس از تغییر تنظیم دوباره راه‌اندازی شود.
- کاربران مشتری با رمز قدیمی کمتر از ۸ نویسه باید پیش از ورود رمز خود را بازیابی کنند.
- آزمون ارتباط زنده با درگاه یا ارسال واقعی پیام انجام نشده است.
