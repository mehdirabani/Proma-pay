# Proma Pay V1.4.4 - Final QA Report

تاریخ اجرا: ۱۴۰۵/۰۵/۰۱

وضعیت: موفق در محیط QA محلی؛ گواهی دسترس‌پذیری شبکه تولید نیازمند شواهد هاست است.

## دامنه بررسی

- lifecycle نشست و ثبت flash پس از آزادسازی قفل
- polling اعلان‌ها در چند تب و deadline شبکه
- read-only بودن feed اعلان‌ها
- endpoint عملیات حذف قرارداد
- رابط تأیید اصلاح مشخصات و سلامت سامانه
- مودال‌های موبایل و visual viewport
- lint کامل PHP و JavaScript
- migration و بسته نصب/بروزرسانی

## نتایج خودکار

- PHP lint: موفق برای ۲۹۶ فایل
- تست‌های static و unit هسته و افزونه‌ها: موفق
- تست‌های integration دیتابیس: موفق
- آزمون HTTP چهار نقش مدیریت، اپراتور، وکیل و مشتری: موفق
- آزمون مودال جزئیات قرارداد: موفق
- آزمون نصب نسخه یکسان، نسخه قدیمی، نسخه جدید و حداقل نسخه: موفق
- ارتقای واقعی کپی ایزوله V1.4.3 با updater همان نسخه به V1.4.4: موفق

- اجرای دوباره V1.4.4 پیش از ساخت بکاپ متوقف شد و تعداد بکاپ‌ها بدون تغییر باقی ماند.

- آزمون دیتابیس داشبورد حسابداری: صدک ۹۵ حدود ۱٫۸۹ میلی‌ثانیه

## نتایج تصویری

- صفحات تأیید اصلاح مشخصات و سلامت سامانه در عرض‌های ۱۴۴۰ و ۳۹۰ پیکسل بدون اسکرول افقی و تداخل هدر بررسی شدند.
- مودال افزودن قسط در عرض ۳۲۰ پیکسل و ارتفاع ۵۶۸ پیکسل بررسی شد.
- پس از اصلاح، تمام ردیف‌های مودال ارتفاع طبیعی دارند، هم‌پوشانی ندارند و بدنه داخلی اسکرول می‌شود.

## بروزرسانی

- بسته هم‌نسخه پیش از ساخت بکاپ، نوشتن فایل و اجرای migration رد می‌شود.
- بسته قدیمی و بسته‌ای که حداقل نسخه آن رعایت نشده باشد قابل نصب نیست.
- migration نسخه ۱.۴.۳ دیگر لاگ‌های احراز هویت را حذف نمی‌کند و توسط نگهبان دستورات مخرب رد نمی‌شود.

## محدودیت محیط

`ERR_CONNECTION_TIMED_OUT` بدون پاسخ HTTP در لایه بیرون از PHP رخ می‌دهد. اصلاحات این نسخه فشار و الگوهای محرک داخل برنامه را کاهش می‌دهد، اما تأیید رفع blacklist در CSF/LFD، ModSecurity، WAF یا فایروال فقط با لاگ‌های هاست تولید امکان‌پذیر است.
