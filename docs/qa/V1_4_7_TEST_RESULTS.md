# Proma Pay V1.4.7 - Final QA Report

وضعیت: گیت انتشار محلی با موفقیت اجرا شد؛ آرشیوهای core و update آمادهٔ بررسی نهایی هستند.

## دامنه بهینه‌سازی

این نسخه مسیر `contracts` را که در هاست اشتراکی حساس‌ترین صفحه است بازبینی می‌کند. نسخه قبلی برای هر قرارداد قابل نمایش چندین query مستقل برای آمار اقساط، نمودار پرداخت، تایم‌لاین پرداخت، ضامنان، اقلام قرارداد، ضمانت‌ها، اشخاص ضامن و پیش‌نمایش‌های لغو و حذف اجرا می‌کرد. علاوه بر آن، بازدید از فهرست قراردادها یک update سراسری وضعیت قراردادها را اجرا می‌کرد.

در V1.4.7 این کارها به واکشی‌های گروهی تبدیل شده‌اند. داده‌های مودال‌های مخرب نیز هنگام باز شدن همان مودال دریافت می‌شوند، نه برای همه قراردادهای صفحه. این تغییر بدون تضعیف کنترل سرور است: عملیات حذف همچنان پیش از ثبت، وابستگی‌ها را دوباره محاسبه و تأییدهای لازم را بررسی می‌کند.

## کنترل‌های انجام‌شده

- lint فایل‌های تغییرکرده PHP برای مدل قرارداد، پرداخت، سند قرارداد، تنظیمات، کنترلر قرارداد و view فهرست قراردادها.
- تست static برای اطمینان از وجود APIهای batch، حذف queryهای per-card از view، محدود شدن sync وضعیت پرداخت به قرارداد مرتبط، حذف write از `Settings::ensureSchema` و وجود migration ایندکس‌ها.
- migration idempotent با بررسی `information_schema.STATISTICS` برای جلوگیری از خطای index تکراری در نصب‌های قدیمی.
- بررسی اینکه migration هیچ `DROP TABLE`، `TRUNCATE TABLE` یا `DELETE FROM` ندارد و با سیاست updater سازگار است.
- اجرای گیت انتشار کامل: lint، تست‌های static و integration، smoke testهای HTTP مودال‌ها و نقش‌ها، و تست‌های افزونهٔ حسابداری، همگی موفق بودند.
- بررسی build و archive مستقل پس از اجرای release gate: نسخه، manifest، فایل migration، دارایی‌های RTL و checksumها در گزارش build ثبت می‌شوند.

## نتیجه مورد انتظار عملیاتی

یک صفحه کارت قرارداد اکنون به جای تعداد query متناسب با تعداد کارت‌ها، مجموعه‌ای ثابت از queryهای گروهی دارد. در نتیجه latency پایگاه داده، احتمال قفل‌شدن صف PHP-FPM/LSAPI و مصرف CPU روی هاست اشتراکی به شکل محسوسی کم می‌شود. آستانه‌های دقیق به میزان داده و سرویس میزبان وابسته‌اند؛ تله‌متری درخواست سامانه باید پس از انتشار برای مسیر `contracts` پایش شود.

این نسخه نمی‌تواند قطعی شبکه‌ای را که پیش از رسیدن درخواست به PHP رخ می‌دهد رفع کند؛ برای نمونه timeout هم‌زمان `health-static.txt` نیازمند اصلاح وب‌سرور یا فایروال توسط سرویس‌دهنده هاست است. با این حال، فشار تولیدشده توسط خود نرم‌افزار در مسیرهای معمول به‌طور مستقیم کاهش یافته است.
