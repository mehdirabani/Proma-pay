# گزارش آزمون انتشار V1.4.9

## دامنه

این گزارش برای اصلاح رخداد burst مسیر `contracts/preview` و ساخت update تفاضلی تهیه شده است. رخداد میزبان شامل بیش از ۲۰ درخواست متفاوت در یک ثانیه بود. بررسی کد نشان داد صفحهٔ کارت قرارداد، برای همهٔ قراردادهای همان صفحه فرم edit پنهان می‌سازد و نسخهٔ پیشین `initContractForms` در پایان راه‌اندازی هر فرم `updatePreview()` را فراخوانی می‌کرد. در نتیجه چندین درخواست مستقل پیش از هر تعامل کاربر ساخته می‌شد.

## کنترل‌های پیاده‌سازی‌شده

1. تست استاتیک `tests/contract_preview_storm_v149.php` وجود کنترلر یکتا، data-attribute راه‌اندازی، debounce 650ms، لغو، sequence ضد پاسخ کهنه، visibility gate، جلوگیری از درخواست آغازین، no-store، عدم boot افزونه و rate bucket مخصوص را بررسی می‌کند.
2. تست `tests/request_flood_guard_v148.php` ظرفیت مستقل `contract-preview` را با زمان قطعی بررسی می‌کند: درخواست اول پذیرفته، درخواست دوم رد و پس از refill پذیرفته می‌شود.
3. تست استاتیک انتشار اطمینان می‌دهد builder baseline را با `PROMA_UPDATE_BASELINE_ARCHIVE` و `release-manifest.json` می‌خواند.
4. verifier آرشیو hash هر فایل update را با core هدف، baseline واقعی و manifest کنار ZIP بررسی می‌کند؛ فایل بدون تغییر اجازهٔ ورود به update ندارد و تعداد فایل‌های update باید از inventory نصب کامل کمتر باشد.
5. آزمون مرورگر محلی باید بعد از راه‌اندازی QA اجرا شود: بازشدن صفحه قراردادها و مودال create بدون درخواست preview؛ تغییر سریع فیلد مالی در فرم باز دقیقاً یک درخواست؛ بستن مودال لغو درخواست؛ تغییر فرم edit باز نیز فقط یک درخواست.

## معیار پذیرش

- نصب کامل شامل دارایی‌های runtime RTL است.
- update کوچک و تفاضلی است، نه ZIP هم‌اندازهٔ core.
- هیچ درخواست preview در بارگذاری، hydrate Ajax یا بازشدن مودال ایجاد نمی‌شود.
- endpoint ورودی نامعتبر را با HTTP 422 پاسخ می‌دهد و پاسخ‌های موفق `no-store` دارند.
- نسخهٔ قدیمی‌تر از baseline نمی‌تواند این update را نصب کند.

## نتایج واقعی اجرا

### مرورگر محلی

- صفحهٔ کارت قراردادها با ۱۳ فرم قرارداد (ایجاد و فرم‌های ویرایش پنهان) باز شد؛ هر ۱۳ کنترلر راه‌اندازی شد اما هیچ فرم preview بازی وجود نداشت.
- bucket اختصاصی `contract-preview` پس از بارگذاری صفحه اصلاً ساخته نشد؛ یعنی درخواست preview ارسال نشد.
- فرم ایجاد قرارداد با مسیر `open=create-contract` باز شد و پس از ۹۰۰ms نیز bucket preview وجود نداشت.
- چهار مقدار مالی (`principal_amount`، `down_payment_amount`، `months` و `monthly_interest_rate`) پشت سر هم تغییر کردند. پس از debounce، bucket از ظرفیت ۳ به دقیقاً ۲ رسید؛ بنابراین فقط یک درخواست preview انجام شد.
- پاسخ قابل‌مشاهده در فرم: اصل ۱٬۰۰۰٬۰۰۰، پیش‌پرداخت ۲۰۰٬۰۰۰، مانده ۸۰۰٬۰۰۰، قسط ۲۰۰٬۰۰۰ و مجموع ۱٬۶۰۰٬۰۰۰ تومان بود. خطای اعتبارسنجی نمایش داده نشد.

### گیت و آرشیو

- `scripts/build_release.php --local-qa`: موفق؛ ۳۰۰ فایل PHP lint شد و static/unitها، آزمون‌های امنیتی، migration، role/modal HTTP و افزونه‌ها پاس شدند.
- آزمون MariaDB داشبورد حسابداری: ۳۰ iteration، p50 برابر 1.67ms و p95 برابر 2.44ms.
- آزمون HTTP داشبورد حسابداری: ۲۰ iteration، p50 برابر 62.6ms و p95 برابر 73.75ms.
- `tools/verify-release.php`: `RELEASE_ARCHIVES_V149_OK`.
- core V1.4.9 حدود 81.19MB است زیرا نصب کامل شامل همهٔ دارایی‌های runtime لازم است. update V1.4.9 فقط 59.82KB (0.072٪ core) و شامل ۱۱ فایل تغییرکرده است؛ baseline آن `PromaPay-v1.4.8.zip` با hash manifest ثبت‌شده است.

## وضعیت نهایی

قبول برای انتشار محلی. این گزارش گواهی availability تولیدی یا تست مرورگر روی هاست Netafraz نیست؛ اما علت request storm در کد، آزمون مرورگر محلی و bucket ایزوله بازتولید و رفع آن تأیید شده است.
