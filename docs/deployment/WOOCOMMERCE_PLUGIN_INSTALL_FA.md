# نصب و راه‌اندازی افزونهٔ آزمایشی WooCommerce

نسخهٔ `0.8.0-rc.1` انتشار آزمایشی است و فقط اعتبارنامه‌های `pmp_test_` را می‌پذیرد. برای پرداخت زنده، تسویه بانکی، قرارداد حقوقی یا استعلام عملیاتی صیاد از این بسته استفاده نکنید.

## پیش‌نیازها

- WordPress 7.1.3 و PHP 8.3 یا بالاتر.
- WooCommerce 11.2.1؛ checkout کلاسیک و Checkout Blocks در این ترکیب بررسی شده‌اند.
- HTTPS معتبر در WordPress و سامانهٔ مرکزی.
- یک پایگاه دادهٔ پشتیبان‌گیری‌شده برای Proma Pay مرکزی.

نسخه‌های دیگر، Multisite، همهٔ ترکیب‌های قالب/افزونه و پرداخت مرورگری با درگاه بانکی واقعی آزموده نشده‌اند.

## ارتقای سامانهٔ مرکزی

برای نصب تازه از `database/proma-pay-install.sql` همان انتشار استفاده کنید. برای سامانهٔ موجود، ابتدا backup بگیرید و migrationهای افزایشی را به ترتیب اجرا کنید:

1. `2026_10_23_multi_merchant_core_phase2.sql`
2. `2026_10_23_guarantee_engine_phase3.sql`
3. `2026_10_23_settlement_commission_phase4.sql`
4. `2026_10_23_public_api_gateway_phase5.sql`
5. `2026_10_23_checkout_quote_snapshot_phase7.sql`

پیش از فعال‌کردن افزونه تأیید کنید migrationها با موفقیت اعمال شده‌اند. migrationها را در پایگاه‌دادهٔ عملیاتی ابتدا روی clone آزمایش کنید.

## نصب WordPress

1. از **افزونه‌ها ← افزودن افزونه ← بارگذاری افزونه** فایل `PromaPay-WooCommerce-v0.8.0-rc.1.zip` را بارگذاری و فعال کنید.
2. از **Proma Pay** یک اتصال بسازید؛ نشانی پایهٔ API را بدون `/api/v1` وارد کنید، برای نمونه `https://pay.example.test`.
3. فقط token آزمایشی بسازید. برای quote و checkout مجوزهای `merchant.read`, `policy:read`, `quote:create`, `order:create`, `order:cancel`, `contract:write`, `contract:read`, `guarantee:read` لازم است.
4. اتصال را آزمایش و policy مالی/ضمانت را refresh کنید. درگاه پیش‌پرداخت را از بین درگاه‌های آنلاین فعال همان فروشگاه انتخاب کنید؛ `bacs`, `cheque`, `cod` و درگاه اقساطی Proma Pay قابل انتخاب نیستند.
5. در تنظیمات WooCommerce، عنوان، فعال‌بودن، نمایش برآورد محصول و اتصال پیش‌فرض را تعیین کنید. می‌توانید چند اتصال را با اولویت متفاوت نگه دارید.
6. checkout را با محصول و سفارش ساختگی در محیط staging آزمایش کنید. برای Checkout Blocks هر دو افزونهٔ WooCommerce و Proma Pay باید فعال باشند.

## سفارش و بازپرداخت

سفارش اصلی پس از پرداخت بیعانه `on-hold` و پرداخت‌نشده می‌ماند؛ یک child order جداگانه، پیش‌پرداخت را با درگاه انتخاب‌شدهٔ فروشنده می‌گیرد. سامانهٔ مرکزی درخواست را در صف بررسی نگه می‌دارد. فعال‌شدن قرارداد یا وصول مانده از این پرداخت استنباط نمی‌شود.

بازپرداخت جزئی پشتیبانی نمی‌شود. برای بازپرداخت کامل، درخواست معلق باید ابتدا از API لغو شود؛ اگر لغو مرکزی موفق نباشد هیچ بازپرداختی شروع نمی‌شود. سپس gateway انتخابی فروشنده بازپرداخت را انجام می‌دهد. رسید بانکی را جداگانه تطبیق دهید؛ پنل Woo فقط نتیجهٔ gateway را گزارش می‌کند.

## قطع اتصال و ارتقا

- اتصال ناموفق را در تنظیمات غیرفعال کنید و در رخداد امنیتی آن را در هسته مرکزی emergency-disable کنید.
- قطع اتصال یا چرخاندن کلیدهای WordPress باعث می‌شود توکن رمز‌شده قبلی قابل بازیابی نباشد؛ credential آزمایشی را دوباره ثبت کنید.
- افزونه migration مخرب اجرا نمی‌کند؛ schema با `dbDelta` به‌صورت افزایشی ارتقا می‌یابد. پس از به‌روزرسانی به‌عنوان Administrator وارد تنظیمات شوید تا نسخهٔ schema بررسی شود.
- پیش از ارتقا backup بگیرید و سفارش parent/child را در QA تطبیق دهید.

## آزمون‌های ثبت‌شده و مرزها

در WordPress 7.1.3 / WooCommerce 11.2.1 / PHP 8.3.33، checkout با درگاه ساختگی در HPOS و legacy order storage اجرا شده است. این اجرا شامل بانک یا callback زنده نبوده است. آزمون کامل مرورگری Store API/Blocks، settlement بانکی، refund زنده، اسناد حقوقی و تأیید عملیاتی چک صیادی انجام نشده است. این انتشار Production Ready نیست.
