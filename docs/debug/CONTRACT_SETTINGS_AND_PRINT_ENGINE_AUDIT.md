# ممیزی تنظیمات قرارداد و موتور چاپ

## وضعیت پیش از V1.3.0

| مورد | مقدار قبلی |
|---|---|
| حاشیه چاپ | `18mm 17mm` |
| padding پیش‌نمایش A4 | `18mm 17mm` |
| اندازه متن | `10.4px` |
| line-height بدنه | `1.54` ثابت |
| فاصله پاراگراف | `1.4mm` ثابت |
| متن ساده | `nl2br(e($template))` |
| خطوط خالی | هر newline به `<br>` تبدیل می‌شد |
| جدول | header تکرارشونده و row غیرقابل شکست؛ profile مستقل وجود نداشت |
| فاصله هدر | padding داخلی تا 4mm، margin پایین 5mm و حاشیه کاغذ 18mm |
| منبع قالب | `settings.contract_template_body` |
| قالب مؤثر | مقدار setting یا `ContractDocument::defaultTemplate()` |
| نسخه سند | جدول `contract_document_versions` |
| نسخه قالب | وجود نداشت |

## ریشه مشکلات

1. حاشیه `@page` و padding پیش‌نمایش از یک مدل تنظیمات خوانده نمی‌شدند و مقدار بالای 18mm فضای زیادی ایجاد می‌کرد.
2. line-height، اندازه فونت و فاصله‌ها در CSS ثابت بودند و مدیر امکان کنترل امن آن‌ها را نداشت.
3. renderer متن ساده تمام newlineها را به `<br>` تبدیل می‌کرد؛ حذف یا افزودن خطوط خالی ساختار پاراگراف قابل پیش‌بینی نداشت.
4. محتوای قالب و ظاهر چاپ یک مفهوم محسوب می‌شدند و نسخه قالب مستقل از نسخه سند نبود.
5. قالب در فرم بزرگ تنظیمات عمومی ذخیره می‌شد و احتمال submit شدن تنظیمات نامرتبط وجود داشت.
6. HTML قدیمی اجازه style و کلاس‌های دلخواه می‌داد و مرز محتوای مجاز روشن نبود.

## معماری V1.3.0

- `ContractTemplateService`: قالب مؤثر، پیش‌نویس، انتشار، بازیابی، migration و صف بازسازی
- `ContractTemplateRenderer`: پاراگراف، عنوان، لیست، خطوط خالی کنترل‌شده و HTML امن
- `ContractPrintProfile`: preset و validation تنظیمات چاپ
- `contract_templates` و `contract_template_versions`: نسخه‌بندی مستقل قالب
- `contract_document_rebuild_jobs`: پردازش 25تایی قابل ادامه
- `contract_template_audit_logs`: ثبت عملیات بدون اسرار
- تنظیمات مستقل در `settings/contracts/*`

## رفتار اسناد

- تغییر profile چاپ فوراً روی همه چاپ‌ها اعمال می‌شود و متن سند را تغییر نمی‌دهد.
- انتشار قالب جدید، سندهای قدیمی را فقط `outdated_template` علامت می‌زند.
- بازسازی فقط اسناد غیرنهایی را پردازش می‌کند.
- نسخه‌های نهایی قرارداد حذف یا بازنویسی خودکار نمی‌شوند.

## Migration

Migration شماره `2026_07_13_contract_template_print_engine.sql` قالب سفارشی قدیمی را بدون پاک کردن setting قدیمی به نسخه منتشرشده شماره 1 تبدیل می‌کند. فیلد قدیمی تا پایان دوره سازگاری حفظ شده است.
