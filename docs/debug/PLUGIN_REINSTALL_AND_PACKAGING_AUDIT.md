# ممیزی نصب مجدد، کشف و بسته‌بندی پلاگین

تاریخ ممیزی: ۱۴۰۵/۰۴/۲۱  
مبنای کد: V1.2.7  
انتشار اصلاحی هدف: V1.2.8

## وضعیت فعلی

- کشف افزونه فقط پوشه‌های موجود در `plugins/` را پیمایش می‌کند.
- مسیر مطلق runtime مستقیماً با کلید `path` به view داده و در جدول نمایش داده می‌شود.
- حذف عادی وضعیت غیرقراردادی `uninstalled` ثبت می‌کند، اما view برای این وضعیت عملیات نصب مجدد ندارد.
- بارگذاری ZIP در صورت وجود پوشه مقصد همیشه متوقف می‌شود؛ حتی اگر رکورد قبلی حذف یا خراب شده باشد.
- عملیات بازاسکن صریح برای همگام‌سازی filesystem و registry وجود ندارد.
- اسکریپت تکرارپذیر برای ساخت core ZIP، update ZIP و plugin ZIP وجود ندارد.

## ریسک‌ها

1. نشت مسیر کامل هاست در رابط مدیریتی.
2. بن‌بست نصب مجدد پس از حذف یا نصب ناقص.
3. تفاوت وضعیت registry با فایل‌های واقعی.
4. امکان قرار گرفتن ناخواسته پلاگین اختیاری یا داده عملیاتی در بسته هسته.
5. تولید دستی بسته با محتوای متفاوت بین انتشارها.

## تصمیم معماری

- وضعیت‌های canonical: `discovered`، `uploaded`، `installed`، `active`، `inactive`، `failed`، `update_available` و `removed`.
- `PluginManager::displayPath()` فقط مسیر نسبی امن مانند `plugins/PromaAccounting` را برای UI تولید می‌کند.
- مسیر مطلق فقط داده داخلی runtime است و به جدول عادی view ارسال نمی‌شود.
- `discover()` داده filesystem و registry را reconcile می‌کند و رکوردهای بدون پوشه را با وضعیت `removed` قابل تشخیص نگه می‌دارد.
- دکمه بازاسکن، reconciliation را به‌صورت صریح اجرا می‌کند.
- نصب مجدد برای وضعیت‌های `removed` و `failed` مجاز است و migrationهای موفق دوباره اجرا نمی‌شوند.
- بارگذاری جایگزین فقط برای وضعیت امن و غیرفعال مجاز است و با انتقال موقت انجام می‌شود.
- اسکریپت انتشار، پوشه‌های داده عملیاتی و پلاگین اختیاری را از core ZIP حذف و plugin ZIP را جدا تولید می‌کند.

## معیار پذیرش

- رابط عادی فقط `plugins/<PluginDirectory>` را نمایش دهد.
- افزونه حذف‌شده دوباره قابل نصب باشد.
- پوشه بدون registry به حالت `discovered` دیده شود.
- registry بدون پوشه به حالت `removed` دیده شود.
- بازاسکن پیام نتیجه روشن و لاگ ممیزی ایجاد کند.
- بسته هسته شامل `config/database.php`، `installed.lock`، uploadها، backupها، cache و کد پلاگین اختیاری نباشد.
- بسته پلاگین `plugin.json` را در ریشه پوشه افزونه داشته باشد و مستقل اعتبارسنجی شود.
