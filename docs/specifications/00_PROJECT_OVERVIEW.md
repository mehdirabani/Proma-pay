Proma Pay یک سامانه جامع مدیریت فروش اقساطی است که برای مدیریت کامل فرآیند فروش، قراردادها، اقساط، مشتریان، ضمانت‌ها، پرونده‌های حقوقی، تقویم، گفتگو، اعلان‌ها، گزارش‌ها و پرداخت‌ها طراحی شده است.

این پروژه نباید یک پروژه آزمایشی یا نمونه آموزشی باشد.

تمام قابلیت‌ها باید Production Ready باشند.

# هدف Codex

وظیفه Codex فقط تولید کد نیست.

Codex باید قبل از هر تغییر:

- ساختار پروژه را بررسی کند.
- وابستگی‌ها را بررسی کند.
- از ایجاد کد تکراری جلوگیری کند.
- از شکستن قابلیت‌های قبلی جلوگیری کند.
- بهترین راهکار را انتخاب کند.

# قوانین توسعه

قبل از اضافه کردن هر قابلیت جدید:

۱- ابتدا بررسی کن آیا قابلیت مشابهی وجود دارد یا خیر.

۲- اگر وجود دارد آن را Refactor کن.

۳- از ایجاد فایل جدید بدون دلیل خودداری کن.

۴- از ایجاد Helper تکراری خودداری کن.

۵- از ایجاد Query تکراری خودداری کن.

۶- از Copy/Paste کد جلوگیری کن.

۷- تا جای ممکن از Componentهای مشترک استفاده کن.

# معماری پروژه

پروژه بر پایه MVC توسعه داده می‌شود.

تمام کدهای جدید باید از همین معماری پیروی کنند.

هیچ Business Logic نباید داخل View قرار بگیرد.

Controller فقط وظیفه هماهنگی دارد.

Business Logic باید در Serviceها یا کلاس‌های مناسب قرار گیرد.

Model فقط مسئول ارتباط با دیتابیس است.
