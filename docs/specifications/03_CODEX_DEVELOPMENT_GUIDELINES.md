# Proma Pay — Codex Development Guidelines

Version: 1.0

Status: Master Specification

Priority: CRITICAL

---

# معرفی

این فایل مهم‌ترین مرجع توسعه پروژه Proma Pay برای Codex است.

Codex موظف است قبل از اعمال هرگونه تغییر، این فایل را مطالعه و رعایت کند.

این فایل مشخص می‌کند:

- چگونه پروژه تحلیل شود.
- چگونه تغییرات اعمال شوند.
- چگونه از ایجاد کدهای تکراری جلوگیری شود.
- چگونه پروژه در بلندمدت قابل نگهداری باقی بماند.

در صورت وجود تعارض، این فایل نسبت به سایر مستندات توسعه اولویت دارد.

---

# فلسفه توسعه

هدف Codex فقط نوشتن کد نیست.

هدف Codex توسعه نرم‌افزار است.

بنابراین قبل از هر Feature جدید ابتدا باید پروژه تحلیل شود.

هیچ Feature نباید بدون تحلیل وارد پروژه شود.

---

# چرخه استاندارد توسعه

هر Feature باید دقیقاً مطابق مراحل زیر انجام شود.

- UI

# قوانین Migration

Migration آخرین گزینه است.

ابتدا بررسی کن:

آیا جدول وجود دارد؟

آیا ستون وجود دارد؟

آیا Index وجود دارد؟

اگر وجود دارد Migration جدید ایجاد نکن.

Migrationها باید:

Idempotent

Rollbackable

Safe

باشند.

# قوانین Database

هیچ اطلاعات کاربر حذف نشود.

هیچ قرارداد حذف نشود.

هیچ پرداخت حذف نشود.

در صورت نیاز از Soft Delete استفاده شود.

# Definition of Done (DoD)

یک Feature فقط زمانی کامل است که:

- کد نوشته شده باشد.
- Refactor شده باشد.
- تست شده باشد.
- مستند شده باشد.
- UI بررسی شده باشد.
- Responsive بررسی شده باشد.
- Permission بررسی شده باشد.
- Performance بررسی شده باشد.
- مستندات پروژه به‌روزرسانی شده باشند.

در غیر این صورت Feature ناقص محسوب می‌شود.
