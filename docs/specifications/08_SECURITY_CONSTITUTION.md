# Proma Pay — Security Constitution

Version: 1.0

Status: Master Specification

Priority: CRITICAL

---

# معرفی

این فایل قانون اساسی امنیت پروژه Proma Pay است.

تمام قابلیت‌های جدید، اصلاحات، Refactorها و توسعه‌های آینده باید مطابق این سند انجام شوند.

امنیت یک قابلیت نیست.

امنیت بخشی از تمام Featureهای پروژه است.

هیچ بخشی از پروژه از رعایت این قوانین مستثنی نیست.

---

# اصل اول

هیچ داده‌ای قابل اعتماد نیست.

تمام اطلاعات ورودی باید اعتبارسنجی شوند.

حتی اگر اطلاعات:

- از فرم
- از API
- از جاوااسکریپت
- از Ajax
- از Import
- از پنل مدیریت

ارسال شوند.

---

# اصل دوم

Frontend امنیت ایجاد نمی‌کند.

مخفی کردن دکمه‌ها، فیلدها یا منوها به معنی محدود کردن دسترسی نیست.

تمام Permissionها باید سمت Server بررسی شوند.

---

# اصل سوم

تمام عملیات حساس باید قابل ردیابی باشند.

هیچ عملیات مهمی نباید بدون Log انجام شود.

---

# Authentication

تمام کاربران باید احراز هویت شوند.

Sessionها باید:

- امن باشند.
- زمان انقضا داشته باشند.
- بعد از Logout حذف شوند.
- بعد از تغییر رمز عبور باطل شوند.

---

# Authorization

تمام دسترسی‌ها باید بر اساس RBAC بررسی شوند.

هر Route باید قبل از اجرا سطح دسترسی کاربر را بررسی کند.

هیچ Controller نباید بدون بررسی Permission اجرا شود.

---

# CSRF

تمام فرم‌های POST، PUT، PATCH و DELETE باید دارای CSRF Token باشند.

Tokenها باید برای هر Session معتبر باشند.

---

# XSS

تمام خروجی‌های متنی باید Escape شوند.

هیچ داده خامی نباید مستقیماً داخل HTML چاپ شود.

---

# SQL Injection

تمام Queryها باید با Prepared Statement اجرا شوند.

استفاده از Queryهای رشته‌ای ممنوع است.

---

# File Upload

تمام فایل‌های آپلودی باید:

- اعتبارسنجی شوند.
- MIME Type بررسی شود.
- پسوند بررسی شود.
- اندازه بررسی شود.
- نام فایل تغییر کند.
- خارج از Public ذخیره شوند.

---

# محدودیت حجم فایل

مدارک هویتی:

حداکثر 1MB

رسید پرداخت:

حداکثر 1MB

تصاویر چت:

حداکثر 1MB

---

# Image Processing

تمام تصاویر باید:

Compress

Resize

Optimize

شوند.

---

# حذف فایل‌ها

رسید پرداخت:

پس از تأیید یا رد حذف شود.

---

تصاویر چت:

بعد از 7 روز حذف شوند.

---

مدارک هویتی قدیمی:

پس از تأیید نسخه جدید حذف شوند.

---

# Password

رمز عبور فقط به صورت Hash ذخیره شود.

استفاده از MD5 یا SHA1 ممنوع است.

استفاده از password_hash الزامی است.

---

# Session

Session Fixation ممنوع است.

بعد از Login:

Session Regenerate شود.

---

# Brute Force

برای Login محدودیت تعداد تلاش وجود داشته باشد.

پس از چند تلاش ناموفق:

قفل موقت

یا

Delay

اعمال شود.

---

# Import

تمام فایل‌های Import باید:

Scan

Validate

Sanitize

شوند.

---

# Export

کاربر فقط داده‌هایی را Export کند که اجازه مشاهده آن‌ها را دارد.

---

# Payment

تمام Callbackهای پرداخت باید:

اعتبارسنجی شوند.

هیچ وضعیت پرداختی بدون بررسی Gateway تغییر نکند.

---

# API

تمام APIها باید:

Authentication

Authorization

Rate Limit

داشته باشند.

---

# Chat

کاربر فقط گفتگوهای مجاز خود را مشاهده کند.

هیچ Message نباید از طریق تغییر ID قابل مشاهده باشد.

---

# Notification

کاربر فقط اعلان‌های خودش را مشاهده کند.

---

# Calendar

کاربر فقط رویدادهای مجاز خود را مشاهده کند.

---

# Logs

Logها نباید توسط کاربران حذف شوند.

---

# Error Messages

هیچ Error فنی به کاربر نمایش داده نشود.

نمونه‌های ممنوع:

Stack Trace

SQL Error

PHP Warning

Fatal Error

Notice

Pathهای سرور

# Sensitive Data

موارد زیر هرگز نباید در Frontend نمایش داده شوند:

Tokenها

Session ID

# HTTPS

سیستم باید قابلیت اجرای کامل روی HTTPS را داشته باشد.

هیچ URL نباید Hard Code شده باشد.

---

# Cookies

Cookieها باید:

HttpOnly

Secure (در HTTPS)

SameSite=Lax

باشند.

---

# Backup

فایل‌های Backup نباید از طریق مرورگر قابل دانلود مستقیم باشند.

---

# Update

فایل Update باید قبل از اجرا:

Validate

Checksum Verify

شود.

---

# Dependency

هیچ Package ناشناس نصب نشود.

کتابخانه‌های بلااستفاده حذف شوند.

# Security Review Checklist

قبل از Merge هر Feature:

□ CSRF بررسی شد.

□ XSS بررسی شد.

□ SQL Injection بررسی شد.

□ Permission بررسی شد.

□ File Upload بررسی شد.

□ Validation بررسی شد.

□ Logs بررسی شد.

□ Error Handling بررسی شد.

□ Session بررسی شد.

□ Rate Limit بررسی شد.

□ Sensitive Data بررسی شد.

---

# Definition of Done

یک Feature از نظر امنیتی زمانی کامل است که:

✔ هیچ ورودی بدون Validation نداشته باشد.

✔ هیچ خروجی بدون Escape نداشته باشد.

✔ Permission سمت سرور بررسی شده باشد.

✔ Log ایجاد شده باشد.

✔ فایل‌ها ایمن ذخیره شوند.

✔ Session ایمن باشد.

✔ Queryها Prepared باشند.

✔ اطلاعات حساس در Frontend نمایش داده نشوند.

✔ هیچ Fatal Error قابل مشاهده نباشد.

✔ تست امنیتی اولیه با موفقیت انجام شده باشد.
